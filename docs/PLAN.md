# 塔罗网页应用 · 实施计划 v0.1

> 日期：2026-10-09 ｜ 状态：D1–D3 已确认，进入 M0 ｜ 输入：《网页塔罗牌应用研究报告：面向"奥德赛时期的迷茫年轻人"》

## 0. 定位（一句话）

**给深夜迷茫的年轻人一次 2 分钟的"结构化自我对话"**：随机抽牌提供外部符号，AI 帮忙拆问题、给多种读法和一个小行动，解释权留给用户。不卖"准"，卖"被接住 + 有下一步"。

---

## 1. 对报告的取舍（直接判断）

报告的方向（反思而非预测、移动优先、免费摘要 + 付费深度）是对的。但有几处我不照搬：

| 报告建议 | 我的判断 | 理由 |
|---|---|---|
| 订阅/付费墙列为 MVP P0 | **改为"假门测试"，MVP 不接真实支付** | MVP 要验证的是"是否愿意付费"，假门（点击付费按钮 → 记录意向 + 进候补名单）就能回答，且省掉支付资质、退款、订阅合规的全部成本。真实支付放到数据过线之后。 |
| AI 一次生成 3 种风格解读 | **默认 1 种，"换个视角"按需再生成** | 深夜手机场景下 3 段长文是阅读负担，也是 3 倍成本。按需生成同时得到一个干净的意愿信号（谁点了"换视角"）。 |
| 免费层用静态牌义 | **免费层也用 AI，但短（小模型、约 200 字）** | 3 张牌的静态牌义拼接读起来就是套话，恰好是竞品差评的来源；免费层不能让人觉得"没用"。小模型成本可忽略。 |
| 竞品多、牌阵多 | **MVP 只做 1 个牌阵：3 张（处境 / 阻碍 / 下一步）+ 每日一张** | 报告自己的结论是"牌阵越多越好"不成立。牌阵选择本身就是迷茫者的又一次决策负担。 |
| 研究建议"先自解后 AI" | **采纳，但做成可跳过的一行输入** | 这是和竞品真正拉开差异的点（HCI 研究支撑），但强制会掉完成率，做成 A/B。 |
| 卡牌百科 | **保留并提前做成 SEO 页** | 78 张牌 × 正逆位的静态页是零成本的自然流量入口，且 AI 解读需要它做事实底座。 |

报告没覆盖、但会卡住项目的问题见 §2 和 §9。

## 2. 需要你拍板的决策（影响架构，开工前定）

### D1. 目标市场 —— 最大的岔路口
| 选项 | 影响 |
|---|---|
| **A. 先海外部署、中文界面、小范围验证（推荐）** | Vercel 部署，用 Claude API，无需 ICP 备案；不面向大陆公众大规模推广。用 2–4 周拿到真实指标，再决定是否投入合规成本。 |
| B. 直接面向中国大陆公众 | 需要 ICP 备案（需主体）、生成式 AI 服务的算法/大模型备案或登记、只能用已备案的国内模型、境内云；占卜类内容有被认定为"封建迷信"的审核风险。个人开发者周期以月计。 |

**默认按 A 规划**，架构上把模型调用封装成 provider 接口，日后可切国内模型。

**✅ 已确认（2026-10-09）：选 A，先海外部署。**

### D2. 牌面美术
**✅ 已确认：原版先上线，AI 重绘作为并行工作流替换。**
- 上线版本：1909 年原版 RWS（Pamela Colman Smith）公有领域扫描件，只取原始扫描，不用 U.S. Games 等后期重绘/上色版本，每张记录来源。
- AI 重绘：以原版构图为参考做风格化重绘（保留可辨认的象征元素，塔罗用户靠这些认牌）。流程：
  1. 定风格：先出 3 张样张（大阿卡纳 0 愚者、XVII 星星、小阿卡纳 1 张），定稿风格描述 + 参考图
  2. 批量：按定稿参数跑 78 张 + 牌背，逐张人工检查象征元素是否缺失、手部/文字是否崩坏
  3. 替换：图片路径通过 `deck` 配置切换，原版保留为备选牌组
- 风险：AI 生成图在多数法域著作权保护弱，别人可以复用——不影响使用，但别把它当护城河；78 张风格一致性是主要难点，样张阶段必须锁死。

### D3. 是否需要账号
**✅ 默认采纳：MVP 无账号**，匿名 ID + 本地 IndexedDB 存历史。云同步等指标过线再做。

## 3. MVP 范围

### 做（In）
1. 落地页：一句话 + "开始"按钮，首屏可交互 < 1.5s（4G）
2. 引导式起问：选主题（事业 / 关系 / 自我 / 去留）→ 示例问题 / 自由输入 / "我不知道问什么"模式
3. AI 问题改写：把模糊表述改成可反思的问题，用户确认或修改
4. 抽牌仪式：长按洗牌 + 点选/滑动抽牌，**有"快速抽牌"按钮**，动画总时长 < 6s 可跳过
5. 翻牌 + 每张牌：名称、正逆位、3 个关键词
6. 免费解读（流式）：整体一段 + 每张牌一句 + 1 个 24 小时内能做的小行动 + 1 个反问
7. "换个视角"：温和支持 / 理性拆解 / 挑战提问（按需生成）
8. 深度解读 **假门**：展示目录预览 + 价格方案 → 点击即记录意向 + 留邮箱候补
9. 历史记录：本地自动保存，可加情绪标签、写一句回看笔记
10. 次日回访钩子：结束页"明天回来看看这个行动做了没"（PWA 安装提示 / 加书签，不做 push）
11. 分享卡片：默认只含牌面 + 一句话，问题原文默认隐藏
12. 卡牌百科：78 张静态页（SSG）
13. 安全护栏：危机内容识别 → 停止占卜流程，展示求助资源
14. 埋点：漏斗事件，**不采集问题原文**

### 不做（Out，写明避免范围蔓延）
真实支付、账号/云同步、凯尔特十字等高级牌阵、TTS/音频、真人咨询、社区、多语言、原生 App、推送通知。

## 4. 核心流程

```
落地页 → 选主题 → 输入/选问题 → [AI 改写确认] → 洗牌抽牌(可快进)
      → 翻牌 + 关键词 → [可选：你先看到了什么？一行]
      → 免费解读(流式) → 小行动 + 反问 → 自动保存
      → 分支：换个视角 / 深度解读(假门) / 分享 / 结束页(明天回来)
```

目标：从"开始"到读完免费解读 **≤ 120 秒**。

## 5. 技术架构

### 5.1 技术栈
| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | Next.js（App Router）+ TypeScript | 百科页需 SSG/SEO，分享页需 OG 图，AI 需服务端路由；一个框架全覆盖 |
| 样式 | Tailwind CSS | 移动优先迭代快 |
| 动画 | CSS transform + Motion（framer-motion） | 洗牌/翻牌用 3D transform 足够，不上 WebGL |
| 本地存储 | Dexie（IndexedDB） | 历史记录离线可用 |
| AI | Claude API：`claude-haiku-5-5`（改写、免费解读、安全分类），`claude-sonnet-5-5`（换视角、深度解读） | 流式输出；模型 ID 集中在一个配置文件 |
| 限流 | Upstash Redis（按匿名 ID + IP） | 防刷，控成本 |
| 埋点 | PostHog（或 Umami） | 漏斗 + 实验分组 |
| 部署 | Vercel | 零运维 |
| PWA | next-pwa / 手写 manifest + SW | 加到主屏，接近 App 体验 |
| 测试 | Vitest（逻辑）+ Playwright（移动端 E2E） | |

### 5.2 目录结构（初稿，M0 落地后写入 CLAUDE.md）
```
src/
  app/                  # 路由：/、/reading、/history、/cards/[slug]、/api/*
  components/           # UI 组件
  features/
    draw/               # 洗牌、抽牌、随机数（纯函数 + 组件）
    reading/            # 解读流程状态机
    history/            # Dexie 存取
    safety/             # 危机识别
  lib/
    ai/                 # provider 接口、模型配置、流式封装
    analytics/
content/
  cards/                # 78 张牌数据 JSON（牌义、关键词、领域）
  spreads/              # 牌阵定义
  prompts/              # 版本化 prompt（v1/, v2/…）
public/decks/<deck-id>/  # 按牌组分目录的牌面图 + SOURCES.md
evals/                  # prompt 评测集与评分脚本
docs/                   # PLAN、决策记录、研究报告
```

### 5.3 关键设计约束
- **随机性**：抽牌在客户端用 `crypto.getRandomValues` + Fisher–Yates，**模型永远不参与选牌**。牌面结果作为输入传给 AI，服务端校验牌 ID 合法。
- **AI 输出结构化**：解读用 JSON schema（`summary` / `cards[]` / `action` / `question` / `perspective`），前端渲染，便于做"短/长"分层和假门预览。
- **Prompt 原则**（写进 system prompt 并做评测）：不预测具体事件、不用"一定/注定"、给至少两种读法、以反问收尾、行动必须 24 小时内可执行。
- **牌义底座**：AI 解读时注入该牌在 `content/cards` 中的牌义，减少胡编，保证全站口径一致。
- **安全**：输入先过关键词 + 小模型分类；命中自伤/危机 → 不进入占卜，展示求助资源页（资源按地区配置，上线前逐条核实）。
- **隐私**：问题文本只在本地存储和单次 AI 请求中出现；服务端不落库、日志脱敏、埋点只记主题类别。

### 5.4 数据模型（本地）
```ts
Reading {
  id, createdAt, topic, question, spreadId,
  cards: { cardId, position, reversed }[],
  selfNote?,            // 用户先自解的一行
  interpretations: { perspective, content, promptVersion }[],
  moodTag?, revisitNote?, revisitedAt?
}
```

## 8. 指标与实验

### 验证门槛（M4 结束时对照）
| 命题 | 指标 | 继续的门槛（初定） |
|---|---|---|
| 能在 2 分钟内被安顿 | 开始 → 读完免费解读 完成率；结束页"有帮助"自评 | ≥ 60%；正向 ≥ 50% |
| 会回来 | 48 小时内回访率（同匿名 ID） | ≥ 15% |
| 愿意付费 | 假门点击率 / 留邮箱率 | 点击 ≥ 8%，留邮箱 ≥ 3% |

### 首批 A/B（流量够再开，每组至少数百完成样本）
1. 先自解（一行输入）vs 直接看 AI —— 看完成率与回访率
2. 假门位置：免费解读之后 vs 解读中段
3. 默认视角：温和支持 vs 理性拆解

## 9. 风险与合规清单

| 风险 | 应对 |
|---|---|
| 面向大陆推广的合规（备案、生成式 AI 规定、迷信内容审核） | D1 选 A 先规避；推广话术统一为"自我反思工具" |
| 用户在脆弱状态下被强断言刺激 | prompt 禁止断言 + 评测集覆盖 + 危机分流 + 结束页软提示 |
| AI 成本被刷 | 匿名 ID + IP 限流、每日免费次数、小模型做免费层 |
| 牌面版权 | 只用 1909 原版扫描并留来源；不用任何重绘版 |
| 隐私（情感/心理信息） | 本地优先、服务端不存问题文本、分享默认脱敏、可一键清空历史 |
| "不准"差评 | 产品语言从不承诺准确；把价值锚在"行动 + 反问" |
