## 0. 定位

**给迷茫的人一次简短的"结构化自我对话"**：随机抽牌提供外部符号，AI 帮忙拆问题、给几种读法和一个小行动，解释权留给用户。不卖"准"，给"被接住 + 有下一步"。两分钟是待观察的体验目标，不是已验证的完成时间承诺。

形态：GitHub 公开仓库，任何人 `git clone` → 填自己的 API key（可选）→ `pnpm dev` 或 Docker 跑起来。

## 2. 对研究报告的取舍

| 报告建议 | 现在的做法 | 理由 |
|---|---|---|
| 订阅/付费墙/点数 | **不做** | 自托管作品没有变现需求；"深度解读"作为功能直接开放 |
| AI 一次生成 3 种风格 | **默认 1 种，"换个视角"按需生成** | 深夜手机上 3 段长文是负担，也省 token |
| 免费层用静态牌义 | **无 key 时用牌义 + 规则模板；有 key 时在第一次提交前明确选择本地 / AI** | 选择全程本地必须连问题改写也不调用模型，不能等问题已发出再选择 |
| 多种牌阵 | **3 张（此刻 / 阻碍 / 下一步）+ 每日一张**，凯尔特十字放最后 | 牌阵选择本身就是迷茫者的决策负担 |
| 先自解后 AI | **采纳，做成可跳过的一行输入** | 产品假设（研究报告原文出处待补，未补前不作为已证实依据） |
| 记录与复盘 | **保留，作为长期价值核心** | 本地 IndexedDB；私密完整备份按约定范围无损恢复，分享导出另走白名单（见"导出边界"） |
| 分享海报 | **保留为本地导出图片**，默认只含白名单字段 | 不依赖服务端；默认不含主题、时间等任何个性化字段，字段清单见"导出边界" |
| 安全护栏 | **保留** | 对任何使用者都必要 |

## 3. 功能范围

### 做
1. 引导式起问：选主题（事业 / 关系 / 自我 / 去留）→ 示例问题 / 自由输入 / "我不知道问什么"
2. AI 问题改写（有 key 且用户已选择 AI 时）：把模糊表述改成可反思的问题，用户确认或修改；发送前说明传输内容，可跳过
3. 抽牌仪式：长按洗牌 + 点选抽牌，可"快速抽牌"跳过，动画 < 6s
4. 翻牌：牌面、正逆位、关键词
5. 先自解（可跳过）："你第一眼看到了什么？"
6. 解读（受控流式）：默认一种语气，含整体 + 每张牌（折叠）+ 两个简短读法候选 + 一个可编辑的 24 小时小行动 + 一个开放反问；读法可标记"不符合我的情况"；小行动默认未决定，用户操作后才记录接受 / 修改 / 跳过
7. 换个视角：温和支持 / 理性拆解 / 挑战提问
8. 本地模式：不调用模型 API，按"此刻 / 阻碍 / 下一步"用牌义 + 规则模板组织解读与行动引导（无 key 时唯一路径，有 key 时可主动选择）
9. 历史：自动保存（记录含牌组与设置快照）、情绪标签、回看笔记、行动复盘、私密完整备份 / 导入 JSON、一键清空；未决定行动不等于接受，更不等于完成
10. 每日一张
11. 卡牌百科：78 张静态页
12. 导出分享图（本地生成，默认只含"导出边界"白名单字段；任何个性化文本须逐项主动选择并预览）
13. 安全护栏：危机内容识别 → 中止占卜，展示求助资源；误判可返回修改原文并保留输入，不提供"无视警告继续占卜"
14. 设置页：API key 状态提示、正逆位开关、牌组切换

### 不做
付费、账号、云同步、埋点、线上部署、真人咨询、社区、推送。

## 4. 核心流程

```
首页 → 选主题 → 输入/选问题 + 确认本地/AI模式及发送说明 →〔安全检查①〕
    → [仅 AI 模式：可跳过的改写确认] → 洗牌抽牌(可快进)
    → 翻牌 + 关键词 → [可选：你先看到了什么？]
    →〔安全检查②：确认后的问题 + 自解〕→ 解读(AI 受控流式 / 本地)
    → 自动保存结果快照 → 可选：选择读法 + 接受/修改/跳过小行动 → 更新同一条记录
    → 换个视角 / 导出图片 / 回看历史（M3）
安全检查命中 → 中止占卜，展示求助资源；本地规则与 AI 路径都执行，AI 故障不会让命中内容转去普通解读。
误判申诉 → 返回上一步并保留已输入原文，编辑后重新走检查；不提供绕过分流的"继续占卜"出口。
保存失败 → 保留当前结果，提示未保存并提供重试；开始新问题前说明当前结果尚未保存。恢复承诺先覆盖已提交的步骤，未提交的输入须有清晰边界。
```

## 5. 技术架构

| 层 | 选型 |
|---|---|
| 框架 | Next.js 16（App Router）+ React 19 + TypeScript |
| 样式 / 动画 | Tailwind 4 + CSS 3D transform（必要时 Motion） |
| 本地存储 | Dexie（IndexedDB） |
| AI | `@anthropic-ai/sdk`，经 `src/lib/ai/provider.ts` 接口调用；key 来自 `.env.local` |
| 数据校验 | Zod（牌义数据、AI 结构化输出、API 入参） |
| 测试 | Vitest（逻辑）+ Playwright（移动端 E2E，M2 起） |
| 运行 | `pnpm dev` / `pnpm build && pnpm start` / Docker（M3） |

### 关键约束
- 抽牌只在客户端用 `crypto.getRandomValues`，模型不参与选牌（`src/features/draw/`）。服务端按 `spreadId` 决定牌数与位置，用 `isValidDraw` 校验，并核对模型输出的牌 ID / 位置与原抽牌一致
- AI 解读注入该牌在 `content/cards` 中的牌义作为底座，输出 JSON schema 结构化；Zod + 业务校验通过后才算完成
- 流式先确认本次输出的 `crisis` 是布尔值 `false`，再推送已解析、已校验的章节；未确认前缓冲，不依赖 JSON 字段顺序。缺失 / 类型错误 / 重复矛盾标记视为无效输出；`true` 立即中止并清空预览。只有完整校验成功的结果进入记录
- Prompt 原则：不预测具体事件、不用"一定/注定"、不凭牌面确认用户处境或他人动机、两种读法、以反问收尾、行动 24 小时内可执行
- 问题原文只在浏览器本地存储和用户已选择的 AI 操作请求中出现，服务端不落盘、不打日志；全程本地不触发改写或解读 API。AI 改写、解读、重试及换视角均可能再次发送必要内容，SDK 自动重试也可能增加实际请求次数
- 牌义内容标准：描述状态与张力，不仅凭牌面确认用户处境、他人动机、关系结论或未来事件
- AI 接口只接受 `application/json` 并校验 Origin / Host：跨站"简单请求"（如 text/plain）也不能驱动模型；服务默认只绑定回环地址，局域网 / 手机访问须显式授权（开关或随机访问 token 之类的等价保护），README 写明同网段可调用模型、消耗额度的风险
- 记录保存当时的 `deckId` 与正逆位开关快照；历史与分享按记录快照渲染，切换牌组或设置不追改旧记录；schema 变更先写兼容方案，按项目红线确认后再做迁移

### 解读数据契约（`src/features/reading/contract.ts`）
| 契约 | 内容 |
|---|---|
| `ReadingRequest` | 主题、原问题、确认后的问题、可选自解、`spreadId`、固定抽牌（含正逆位）、`deckId` 与正逆位开关快照 |
| `ReadingResult` | 整体、按 `cardId + position` 的逐牌解读、两个读法候选、小行动、反问、来源 `local / ai` |
| `ReadingRecord` | 稳定 ID、`schemaVersion`、时间、请求快照（含牌组 / 设置快照）、结果快照、用户选择（含未决定状态及明确操作，不能把默认值视为承诺）、内容 / prompt / 模型版本 |
| 流程状态 | 收集输入 → 安全分流 / 牌已固定 → 生成中 → 完成 / 拒答 / 技术失败 / 已取消；保存成功或失败单独反馈 |

恢复规则：鉴权失败提示配置；超时、断流、结果不合格保留已提交的问题、自解和牌，可重试或改用本地；取消、重新开始和离开页面均中止对应请求。所有异步事件（包括危机事件）都要校验会话与请求身份，迟到事件不能改动新流程；进行中禁止重复触发；拒答与技术失败分开显示，不静默转本地。重试和切换来源都不重抽、不重复保存。业务层另设整体 / 无进展超时，初始建议总计 90 秒、流建立后 30 秒无进展即中止，真实模型冒烟后校准；不能将 SDK 的连接等待超时当成流的总时限。

存储规则：完成记录存 IndexedDB；当前流程快照实际存 localStorage。草稿单独版本化并校验结构 / 牌阵 / 状态一致性；损坏或不兼容快照不能使页面无法进入，且不能连带删除有效记录。分别反馈草稿恢复能力与正式记录保存状态；失败重试写同一 ID，保存成功后读回验证。记录 schema 兼容方案先写清；实际数据库 schema 变更、迁移或删除操作仍按项目红线单独确认。本次文档修订不授权执行这些操作。

### 运行模式与隐私承诺
| 模式 | 承诺 |
|---|---|
| 本机浏览器 + 本机服务，本地模式（有 / 无 key） | 服务运行时不调用任何模型 API 即可走完流程；有 key 的全程本地选择目前待 M2 收尾补齐 |
| AI 模式 | 发送前说明：改写、解读及重试等操作分别发送必要内容（问题、自解、牌面上下文） |
| 手机访问电脑 / Docker | 页面与 API 经过运行应用的那台主机；记录存在手机浏览器的站点存储里；默认仅绑回环，局域网开放须显式授权后，同网段设备才能调用 AI 接口（M3c 验收） |
| PWA 断网重开 | M3 单独验收，不在 M2 承诺 |

导出边界：**私密完整备份**与**分享图 / 分享导出**是两个交付，禁止互相套用范围；无损往返仅适用于完整备份。M3a 实施前同步 `CLAUDE.md` 中“导出 / 分享默认不含原文”的笼统表述，保留分享默认去敏的要求。

**完整备份**是用户明确选择后下载的恢复文件，文件名只用日期与短 id、不含问题文字（如 `tarot-backup-YYYYMMDD-<short>.json`）：
- 含：全部已完成记录（请求快照、结果快照、选择、标签、笔记、行动复盘、后续视角快照）、`schemaVersion`、导出时间、内容 / prompt / 模型版本；M3b 起的每日一张记录同样纳入。
- 不含：localStorage 进行中草稿、API key 与配置状态、设备信息；设置项不随备份覆盖本机设置。
- 下载前提示文件含私密明文，可能被浏览器下载目录或系统云盘同步；导入预检、冲突预览与事务写入按 M3 约定 1。

**分享导出白名单**（默认只由以下字段重新组装，白名单外字段一律不进分享）：

| 默认允许 | 默认禁止（个性化内容，须逐项主动勾选并预览才可能出现） |
|---|---|
| 牌名、正逆位、牌阵位置标签、关键词、牌组来源署名 | 原问题、确认后问题、自解、`overall`、逐牌 text、两种读法、小行动（含编辑版）、反问 |
| 固定的项目名 / 免责声明（不含站点地址） | 笔记、情绪标签、行动复盘、换视角内容 |
|  | 主题标签、日期时间、记录 id、站点 URL / 二维码 |

`overall` 与逐牌 text 可能复述原文，永远不属安全字段，不能只删问题原文。含任何个性化文本时必须显式选择并预览，用合成姓名、事件、自解、编辑行动与笔记做泄漏断言。

### 验收分层与证据

- **离线确定性检查**：`pnpm check`，本地固定 40 例结构 / 牌面一致性 100%；mock 证明业务处理，不等于模型输出质量。固定危机集与非危机对照集分别报告，新增混合语境与流式异常。
- **应用集成**：`pnpm e2e`（含生产构建），除无 key 主流程外补浏览器端 AI mock；覆盖真实 API 校验、NDJSON 编解码、错误映射、取消和存储异常。不得用已构造好的 reducer 事件代替整个请求链路。
- **真实模型**：先小规模改写 / 解读冒烟，再跑固定 40 例。记录日期、提交、模型 / prompt / 内容版本、用例 ID、终态、首章节 / 总耗时、失败原因、实际运行数与 effort 设置；首轮冒烟对比 low 与默认 effort 的成功率、延迟和语义分，给出解读是否升级 deep 的判据；无 key 或跳过写“未验收”。报告只用合成输入，原始产物留 `tmp/evals/`，脱敏结论写评审文档。
- **分别计分**：生成成功率可用首轮 ≥90%（至少 36/40）作为可靠性目标，失败必须可恢复；任何被展示 / 保存为完成结果的结构、牌面与安全硬约束必须 100% 合格。固定明确危机集必须分流，非危机对照不得误拦；任一安全失败独立阻塞，不可被总体分数抵消。真实 AI 危机集要逐例落盘并断言，不能只打印命中率。
- **语义与体验**：人工逐例检查是否回应问题、是否凭空判断处境 / 他人动机、两种读法是否有区别、行动是否具体且可自主完成、反问是否开放。记录不通过的例子与修复；结构和禁词不能替代此项。3–5 人观察前移到 M2 收尾稳定后，检查无需指导完成、理解非预测、可以拒绝行动、知道保存位置；系统等待与用户思考分别计时，不能包装为疗效或普遍有效性证据。

### M3 实施前的行为约定

1. **历史与备份**：看保存时的结果快照；模型建议、用户选择、后来行动反馈分开显示。完整备份含版本、请求、结果、选择、笔记及后续视角；预检文件大小、字段、牌 ID、牌阵、结果一致性、重复 ID，预览后事务写入。相同 ID + 相同内容跳过；同 ID 冲突须预览选择，默认保留现有记录，禁止静默覆盖。未来版本明确拒绝；兼容旧版本先写方案。备份范围、文件名与排除项以“导出边界”为准：不含进行中草稿、key 与设备信息。
2. **换个视角**：同一问题和固定牌，新增带版本与来源的视角快照，不覆盖原解读、原行动或编辑内容；失败回到原结果，重复触发不产生重复请求。展开逐牌详情不额外调用模型；首版“深度解读”落实为换视角，不另加无规格的长文入口。
3. **每日一张**：按设备当地日期确定日键，记录当时的时区；同一天返回原牌，刷新或当天切换时区不为同一日键重抽；跨午夜按新日键创建。使用独立的一张牌文案，测试午夜 / 夏令时 / 时区变化，不直接套三张牌模板。
4. **设置与分享**：正逆位设置只影响下一次抽牌；历史按保存时的 `deckId` 与设置快照渲染，切换牌组 / 设置不追改旧记录；key 只展示服务端配置状态。分享默认按“导出边界”白名单重建，用合成姓名、自解、编辑行动和笔记验证不泄漏；含个性化文本时逐项显式选择并预览。
5. **自托管与 PWA**：支持个人单实例，不自然扩成多人共享；服务默认只绑定回环地址，手机 / 局域网访问须显式开启（授权开关或随机访问 token 之类的等价保护），文档写明同网段可调用 AI 接口、消耗额度的风险。先验电脑 + 真手机访问，再验安装与断网重开。定义首访、已缓存断网、刷新、版本更新 / 旧缓存、AI 不可用矩阵；不缓存含问题与结果的 API 响应。核验局域网访问方式对 PWA 的限制，按实测写文档。Docker 验收无 key 启动、静态资源、可选服务端 key，密钥不入镜像、不默认绑 0.0.0.0。
6. **资源维护**：继承上次 R10，抓图先暂存并核对全部图片 / 来源，失败保留上一版完整资源与 `SOURCES.md`；未修复前不把重抓视作安全的更新方式。
7. **求助资源**：交付前给出最低地区覆盖——保留大陆 110 / 120，经官方渠道核实后补英国 Samaritans 与紧急号码、美国 / 加拿大 988，或提供明确的地区选择入口；每条资源记录官方来源、适用地区与复核日期，未核实不写入；固定分流测试不依赖热线号码本身。

| 牌义文案"像套话" | 统一口径：写状态与张力，不写必然结果；每张牌配反思问题 |

### DeepSeek 完整评测（`deepseek-chat`，协议冒烟，**非 Claude 验收**）

同一套 40 例 + 危机集，在 prompt v2、不同提交 / adapter 调整下跑了 4 轮（报告在 `tmp/evals/`，只含合成输入）：

| 轮 | 成功 | 说明 |
|---|---|---|
| 1 | 20/40（50%） | 初版 adapter |
| 2 | 22/40（55%） | adapter 补“不要多余字段 / 恰好 2 个读法”约束 |
| 3 | 28/40（70%） | 增加失败原因归类 |
| 4 | 25/40（62.5%） | 加 temperature 0.3 与禁止 name / title 等键 |

- **未达 90% 目标**，且轮间波动大（50–70%），说明这个 provider 的输出不稳定，不能用单轮数字下结论。
- 失败原因（第 4 轮归类）：28 例里 12 例是 `cards[].` 里多出未知键（schema 是 strict，按设计拒绝）、3 例 JSON 解析失败，其余为空 / 被拒；全部落在可恢复的终态，没有挂起、没有被当成结果展示。
