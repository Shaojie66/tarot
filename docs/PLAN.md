## 0. 定位

**给迷茫的人一次 2 分钟的"结构化自我对话"**：随机抽牌提供外部符号，AI 帮忙拆问题、给几种读法和一个小行动，解释权留给用户。不卖"准"，给"被接住 + 有下一步"。

形态：GitHub 公开仓库，任何人 `git clone` → 填自己的 API key（可选）→ `pnpm dev` 或 Docker 跑起来。

## 2. 对研究报告的取舍

| 报告建议 | 现在的做法 | 理由 |
|---|---|---|
| 订阅/付费墙/点数 | **不做** | 自托管作品没有变现需求；"深度解读"作为功能直接开放 |
| AI 一次生成 3 种风格 | **默认 1 种，"换个视角"按需生成** | 深夜手机上 3 段长文是负担，也省 token |
| 免费层用静态牌义 | **有 key 时默认 AI，也可主动选本地解读；无 key 时用牌义 + 规则模板** | 本地模式保证 clone 下来就能用；有 key 时避免套话 |
| 多种牌阵 | **3 张（此刻 / 阻碍 / 下一步）+ 每日一张**，凯尔特十字放最后 | 牌阵选择本身就是迷茫者的决策负担 |
| 先自解后 AI | **采纳，做成可跳过的一行输入** | 产品假设（研究报告原文出处待补，未补前不作为已证实依据） |
| 记录与复盘 | **保留，作为长期价值核心** | 本地 IndexedDB，可导出 JSON |
| 分享海报 | **保留为本地导出图片**，默认不含问题原文 | 不依赖服务端 |
| 安全护栏 | **保留** | 对任何使用者都必要 |

## 3. 功能范围

### 做
1. 引导式起问：选主题（事业 / 关系 / 自我 / 去留）→ 示例问题 / 自由输入 / "我不知道问什么"
2. AI 问题改写（有 key 时）：把模糊表述改成可反思的问题，用户确认或修改
3. 抽牌仪式：长按洗牌 + 点选抽牌，可"快速抽牌"跳过，动画 < 6s
4. 翻牌：牌面、正逆位、关键词
5. 先自解（可跳过）："你第一眼看到了什么？"
6. 解读（受控流式）：默认一种语气，含整体 + 每张牌（折叠）+ 两个简短读法候选 + 一个可编辑的 24 小时小行动 + 一个开放反问；读法可标记"不符合我的情况"
7. 换个视角：温和支持 / 理性拆解 / 挑战提问
8. 本地模式：不调用模型 API，按"此刻 / 阻碍 / 下一步"用牌义 + 规则模板组织解读与行动引导（无 key 时唯一路径，有 key 时可主动选择）
9. 历史：自动保存、情绪标签、回看笔记、导出 / 导入 JSON、一键清空
10. 每日一张
11. 卡牌百科：78 张静态页
12. 导出分享图（本地生成，默认不含问题）
13. 安全护栏：危机内容识别 → 中止占卜，展示求助资源
14. 设置页：API key 状态提示、正逆位开关、牌组切换

### 不做
付费、账号、云同步、埋点、线上部署、真人咨询、社区、推送。

## 4. 核心流程

```
首页 → 选主题 → 输入/选问题 →〔安全检查①〕→ [AI 改写确认] → 洗牌抽牌(可快进)
    → 翻牌 + 关键词 → [可选：你先看到了什么？]
    →〔安全检查②：确认后的问题 + 自解〕→ 解读(AI 受控流式 / 本地)
    → 选择读法 + 接受/修改/跳过小行动 → 保存本次记录
    → 换个视角 / 导出图片 / 回看历史（M3）
安全检查命中 → 中止占卜，展示求助资源；本地规则与 AI 路径都执行，AI 故障不会让命中内容转去普通解读。
```

## 5. 技术架构

| 层 | 选型 |
|---|---|
| 框架 | Next.js 16（App Router）+ React 19 + TypeScript |
| 样式 / 动画 | Tailwind 4 + CSS 3D transform（必要时 Motion） |
| 本地存储 | Dexie（IndexedDB） |
| AI | `@anthropic-ai/sdk`，经 `src/lib/ai/provider.ts` 接口调用；key 来自 `.env.local` |
| 数据校验 | Zod（牌义数据、AI 结构化输出、API 入参） |
| 测试 | Vitest（逻辑）+ Playwright（移动端 E2E，M2 起） |
| 运行 | `pnpm dev` / `pnpm build && pnpm start` / Docker（M3） |

### 关键约束
- 抽牌只在客户端用 `crypto.getRandomValues`，模型不参与选牌（`src/features/draw/`）。服务端按 `spreadId` 决定牌数与位置，用 `isValidDraw` 校验，并核对模型输出的牌 ID / 位置与原抽牌一致
- AI 解读注入该牌在 `content/cards` 中的牌义作为底座，输出 JSON schema 结构化；Zod + 业务校验通过后才算完成
- 流式只推送已解析、已校验的章节事件，不把原始 JSON token 显示给用户；只有完整校验成功的结果进入记录
- Prompt 原则：不预测具体事件、不用"一定/注定"、不凭牌面确认用户处境或他人动机、两种读法、以反问收尾、行动 24 小时内可执行
- 问题原文只在浏览器本地存储和对应操作的模型请求中出现（AI 模式下改写、解读各是一次请求），服务端不落盘、不打日志
- 牌义内容标准：描述状态与张力，不仅凭牌面确认用户处境、他人动机、关系结论或未来事件

### 解读数据契约（`src/features/reading/contract.ts`）
| 契约 | 内容 |
|---|---|
| `ReadingRequest` | 主题、原问题、确认后的问题、可选自解、`spreadId`、固定抽牌（含正逆位） |
| `ReadingResult` | 整体、按 `cardId + position` 的逐牌解读、两个读法候选、小行动、反问、来源 `local / ai` |
| `ReadingRecord` | 稳定 ID、`schemaVersion`、时间、请求快照、结果快照、用户选择（读法、行动、"不符合"标记）、内容 / prompt / 模型版本 |
| 流程状态 | 收集输入 → 安全分流 / 牌已固定 → 生成中 → 完成 / 拒答 / 技术失败 / 已取消；保存成功或失败单独反馈 |

恢复规则：鉴权失败提示配置；超时、断流、结果不合格保留问题、自解和牌，可重试或改用本地；取消后忽略迟到结果；进行中禁止重复触发；拒答与技术失败分开显示，不静默转本地。重试和切换来源都不重抽、不重复保存。

### 运行模式与隐私承诺
| 模式 | 承诺 |
|---|---|
| 本机浏览器 + 本机服务，无 key | 服务运行时不调用任何模型 API 即可走完流程 |
| AI 模式 | 改写、解读各发送一次所需内容（问题、自解、牌面上下文） |
| 手机访问电脑 / Docker | 页面与 API 经过运行应用的那台主机；记录存在手机浏览器的站点存储里 |
| PWA 断网重开 | M3 单独验收，不在 M2 承诺 |

### 目录
```
src/app/            路由：/、/reading、/history、/daily、/cards、/cards/[id]、/settings、/api/*
src/features/       cards / draw / reading / history / safety
src/lib/ai/         模型配置、provider 接口与实现
content/cards/      牌义数据（按大阿卡纳与四花色分文件）
content/spreads/    牌阵定义
content/prompts/vN/ 版本化 prompt
content/questions.json  示例问题库
public/decks/<id>/  牌组图片 + SOURCES.md
scripts/            数据抓取与生成脚本
evals/              prompt 评测集
```

## 7. 风险

| 风险 | 应对 |
|---|---|
| 用户在脆弱状态下被强断言刺激 | prompt 禁止断言 + 评测集覆盖 + 危机分流 + 软提示 |
| 牌面版权 | 只用 1909 原版扫描并留来源；AI 重绘基于公有领域原图 |
| 隐私 | 本地优先；问题只在浏览器本地和对应操作的模型请求中出现；服务端不落盘、不打日志；一键清空（M3） |
| 自托管门槛 | README 一步一步写；无 key 也能用；Docker 一条命令 |
| 牌义文案"像套话" | 统一口径：写状态与张力，不写必然结果；每张牌配反思问题 |
