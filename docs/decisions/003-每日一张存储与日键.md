# 003 · 每日一张的存储与日键规则

- 日期：2026-10-09
- 状态：已采纳（M3b 实施中的决定；用户可推翻）
- 输入：`docs/PLAN.md` M3 行为约定 3

## 决定

1. **日键 = 设备当地日期**（`Intl` 按 IANA 时区计算 `YYYY-MM-DD`）。同一日键只抽一次：刷新、重进、当天改设置都返回原牌；跨午夜按新日键新抽。夏令时回拨 / 跳时日由 `Intl` 处理，测试覆盖伦敦 / 纽约切换日。
2. **记录抽牌当时的 `timeZone`、牌组和正逆位设置快照。** 当天中途切换时区，日键由“切换后的当地日期”重新计算：同一当地日期仍是原牌；若切换使当地日期变了，就是新的一天（这是对“日期”的忠实定义，不是重抽 bug）。
3. **进入 `/daily` 不自动抽牌**，用户点一下才固定今天的牌；已经抽过就直接显示。
4. **存储用 localStorage（`tarot:daily:v1`），不新增 IndexedDB 表。** 原因：新增 object store 需要 Dexie `version(2)`，属于数据库 schema 变更，按项目红线要先确认；每日一张数据极小（一年约 365 条，已设 400 条上限），localStorage 够用。如果以后要和三张牌记录统一查询 / 事务，再单独提方案。
5. **文案独立**：用牌义的关键词、牌义、反思问题加一句固定的“留意一次”提示，不用“此刻 / 阻碍 / 下一步”模板；78 张 × 正逆位全部过文案红线测试。
6. **备份**：`daily` 作为备份文件里的可选字段（`backupVersion` 仍为 1，旧备份没有该字段照常可导入）。导入只补本机没有的日键，已有的不覆盖；记录与每日一张的写入失败时整体回滚。`清空全部`同时清除每日一张。

## 已知取舍

- localStorage 在隐私模式 / 配额满时可能写不进去：页面提示“刷新后可能会变”，不阻止查看。
- 两个标签页同时第一次抽同一天：先写入的为准，后到的读到后直接返回，不会出现两张不同的牌（读后写之间有极小窗口，未做跨标签锁；对个人单实例可接受）。
