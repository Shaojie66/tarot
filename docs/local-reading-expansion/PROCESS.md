# 本地解读 v2 扩写流程（12 张 → 78 张）

> 状态与覆盖率：[STATUS.md](STATUS.md)（`pnpm local:coverage` 生成）。写作规范：[STYLE.md](STYLE.md)。批次计划：[batches.json](batches.json)；评审记录：[reviews.json](reviews.json)。
> 本文件是扩写开始前先定下的约束（先写规则、再动手）。改流程先改这里，再改做法。

## 0. 为什么需要流程

- 普通抽牌里“三张都有 v2 内容”的概率是 C(n,3)/C(78,3)：现在 n=12 → **0.289%**，n=30 → 5.3%，n=60 → 44.9%，n=78 → 100%。在全牌完成之前，大多数用户看到的仍是 v1 模板，所以扩写是这条线的真正交付。
- 十轮 AI 盲评表明：**结构和语气可以靠规则与测试守住，质量判断不能**。批量起草之后没人把关，会把“评审者共同偏好”和“真人是否觉得有用”混为一谈。所以每批都要有人工评分。

## 1. 角色

| 角色 | 谁 | 做什么 |
|---|---|---|
| 起草 | Claude（一次一批） | 按 STYLE.md 写 6 张牌 × 2 个朝向，补标记 / 变体 / 必要的新主张 |
| 自动关口 | 测试与脚本 | schema、全文扫描、组合扫描、覆盖率 |
| AI 预审 | Claude 子智能体 + 其他模型（DeepSeek） | 盲评，找硬伤；**不是放行依据** |
| 人工评审 | 你（产品负责人 / 编辑）；有条件时再加 1–2 人 | 对该批评分表逐例打 0–2 分，放行或打回 |

## 2. 单位与批次

- **工作单位**：一张牌的两个朝向（`upright` + `reversed`）共 2 份内容，字段见 STYLE.md §6。一张牌只有两个朝向都写完才算“已写完”（路由才会用到）。
- **批次**：6 张牌 / 批（12 个朝向），共 11 批待写，顺序见 `batches.json`（大阿卡纳 → 权杖 → 圣杯 → 宝剑 → 星币）。批次小是为了让人工评分做得完、问题能早发现；批次内的牌可以按需要互换，批次之间的顺序调整要写进变更记录。
- **一批只有“全部写完 + 通过关口”才合并**；半批不合并（路由要求三张牌都有内容，半批也不会生效，但会污染覆盖率统计）。

## 3. 每批的六步

1. **起草**：只改 `content/local-reading-v2.json`（新增牌条目，必要时新增标记 / 主张 / 变体）和 STYLE.md 里的标记词表。**不改 v1 模板、不改牌义数据**（共用牌义文件改动会影响百科和 AI 注入）。
2. **自动关口**（全部通过才进入下一步）：
   - `pnpm check`（schema 严格校验、`local-quality.test.ts` 的全文扫描：延后措辞、关系句口径、`oneLine` 以“可能”开头且不是逐牌说明、预设短语；`local-sweep.test.ts`：所有已写完牌的三牌组合，抽样或全遍历，检查结果的硬约束与已知坏句式）。
   - `pnpm local:coverage`：更新 STATUS.md，确认该批的牌都显示 ✓。
   - 跑一遍 `pnpm build` 和 `pnpm e2e`（本地解读路径在 E2E 里被使用）。
3. **生成评分表**：`BATCH=n pnpm vitest run evals/print-batch-samples.test.ts` → `batch-n-samples.md`（每张新牌 × 2 个与旧牌的组合，轮换位置 / 正逆位 / 主题 / 意图，共 12 例）。已有的评分表如果是别的内容版本，生成器会先把它另存为 `batch-n-samples.<旧版本>.md` 再写新表（评语和修订前的原文都留着）；同一版本且已经带评语的表不会被覆盖，要重跑先手动另存。
4. **AI 预审**（可选但建议）：把评分表交给子智能体和 `scripts/judge-local-samples.mjs` 的同类脚本做盲评，目的是在人工评分前清掉硬伤；结果记进 reviews.json 的 `aiPrescreen`，**不能填 `humanReview`**。
   - 按当前版本逐例做的 **AI 编辑审读**（已知版本、无旧版对照）单独记在 `aiEditorialReview`：保存日期、评审身份、五项分数、问题原句、修复方向和总评。可在评分表原文后追加署名评语，保留真人评分空栏；不得称为盲评或人工验收，不改变批次放行状态。
5. **人工评分**：评审人逐例打五项（观点 / 三牌 / 主题 / 行动 / 语言，各 0–2）。**放行门槛：每例 ≥8/10 且无单项 0**；任一例不过，写明哪句话不通过，打回修改，修改后至少复评不通过的例子和同牌的其他组合。“同牌的其他组合”要在**修订之前**按固定公式留出（组合清单记在 `batch-n-heldout.json`，用 `evals/print-combos.test.ts` 渲染修订前后的结果），不用于改稿，防止只把评分表里的例子改好看。结果（评审人、人数、日期、各例分数、不通过的句子）写进 reviews.json 的 `humanReview`。
6. **合并**：提交一个批次一个提交（提交说明写批次号和牌名），更新 `batches.json` 状态为 `accepted`、版本号。**推送前必须问用户**（CLAUDE.md 红线）。

## 4. 跨批次

- 扩写的主要风险是“新牌与旧牌组合出问题”。两道防线：① `local-sweep.test.ts` 自动把新牌放进所有已写完牌的三牌组合里扫描（硬约束，不判断质量）；② 评分表里每张新牌固定与两张旧牌组合，并轮换位置，人工评分覆盖这些组合。
- **新增共同解释（focus）后**必须重跑扫描并看命中分布（日志里 `主张命中`），防止新主张“吃掉”原来走别的主张的组合；并按 STYLE.md §7 先写预先保留的组合。
- **牌族检查**：每批里属于“合作 / 学习 / 离开”牌族的牌，必须在关系、自我、去留三个主题里各过一遍（评分表的主题轮换尽量覆盖；不够就加例）。

## 5. 版本、回退与旧记录

- `content/local-reading-v2.json` 的 `version` 在每批合并时升一位（建议 `local-v3-batch<n>`）；记录的 `versions.content` 会带 `+<version>`，旧记录按快照读取，**不重算**。
- v1 模板（`content/local-reading.json`）**永远保留**作为兜底：任一张牌没有 v2 内容，整个结果回退 v1，不拼半新半旧。
- 回退一批：从 JSON 里删掉该批牌的条目即可，路由会自动回到 v1；不需要数据迁移。

## 6. 完成的定义

全部 78 张牌两个朝向写完，且：① `local-sweep` 在全牌上通过（抽样 ≥20000 个组合）；② 每批人工评分通过并记录；③ 全量人工评分之外，再做一次**跨批次的人工评分**（随机 24 个组合，每例 ≥8/10 无单项 0，评审人注明人数）；④ 路由覆盖率 100%（STATUS.md 显示）；⑤ `pnpm check` / `pnpm build` / `pnpm e2e` 通过；⑥ 在 PLAN.md 记录验收，**不宣称“用户已认可”**——这是评审通过，不是用户研究。真人观察（N4）仍是独立的未完成项。

## 7. 不做的事

- 不穷举 78 张牌的全部三牌组合正文；不随机换句；不为提高命中率而偏置抽牌（抽牌只用 `crypto.getRandomValues`，与内容无关）。
- 不让本地规则读问题正文；不把问题复述当成“回应了问题”。
- 不一次整批起草 66 张牌：一批一批做，每批都要评分，评审意见回流到 STYLE.md。

## 9. v2.11 固定对照与验收

先登记计划与规范，再固定 batch-0-heldout.json 的 heldout3（种子 2026101103）：四主题 × 三意图各两例、三后备主张 × 三意图至少两例。仅依据牌阵/标签/路由分层，排除已有评分、留出、牌族、预留、冻结和本轮已审读的牌阵。保存公式、排除集摘要、基线版本与输入摘要；基线输出在修改前生成但新留出不得用于开发改稿。首次固定还预先指定 18 对版本对照、6 对阻碍/锚牌机制对照及 6 组换末牌对照。评分表、旧 heldout 用作已污染的开发素材。新留出如用于修订须标记已使用，再固定新留出。

固定当前 12 张牌作为回归宇宙，每主题意图遍历 10560 组合，共 126720。比较路由摘要与非后备完整输出摘要；位置对照固定另外两张牌且两边命中同一后备主张，分别统计换牌/翻面，有效对照后续文本变化率必须 100%，阻碍位还要求第一读法变化；不得把重新选主张当成换牌敏感性。全量验证主题保护、陪伴负担的自动部分、关系行动边界与红线，语义部分靠审读。描述性统计同时报告重复成员占比、(N-U)/N、Σn(n−1)/N(N−1)，分主题意图比较，跨层汇总累加分子分母。

候选冻结后才打开新留出，完成 pnpm check / pnpm build / pnpm e2e 并生成保留旧版本的评分表。独立复评只用一位子智能体读一个匿名材料文件：18 对版本对照（含 6 对陪伴）、6 对机制对照、预先固定的换牌对照。逐例记录重点到行动连贯、三牌、主题、行动、语言以及陪伴分析量/任务数/压力/拒绝空间。新版连贯例数不低于旧版、三牌平均分不下降、陪伴无明确负担回退只是小样本护栏，不是质量证明。明确矛盾不能被偏好总票数抵消；若不能修复则记录未达标，不能放宽位置指标或静默切换锚牌。

结果沿用 reviews["0"].revisions 的版本、日期、作者、依据、样本、变更、routing、aiRecheck，并增加 sameness 与 validation；humanReview 及人工放行状态不变。本轮不提交或推送。

实施中全量翻面检查发现宝剑六、星币二、星币三的部分主题 obstacle.check 在正逆位完全相同。为同时守住位置敏感性与非后备不变，先修订 STYLE §8，允许后备 obstacleVariants 的主题 check 专门区分这些朝向；不修改共享牌面字段，也不放宽翻面门槛。

复核材料约定：`evals/local-quality/baseline-v2.10.json` 保存改前输出与全量摘要；`batch-0-v211-metrics.json` 保存当前全量统计；`batch-0-v211-frozen.json` 保存最终 42 例文本及内容、引擎哈希。`V211_REVIEW=1 pnpm vitest run evals/print-v211-review.test.ts` 只在候选冻结时运行一次，拒绝覆盖已有冻结材料，输出单一 `batch-0-v211-blind.md` 与独立解盲表 `batch-0-v211-blind-key.json`。评审只读匿名文件，结果另存 `batch-0-v211-review.json`，不能回填人工评分。冻结后若继续改稿，须保留这些材料并开启新留出轮次。

首轮 AI 护栏未通过：连贯 16/18 → 7/18，陪伴 4/6 增负。该候选保留为 round1，不再作为最终分数。继续修订前固定 heldout4，排除此前全部材料与 heldout3；基线仍由原 v2.10 引擎与内容重建并核对摘要。后续材料文件名增加 round2；只复用原一位评审，新增匿名材料追加到同一个输入文件中，评审只评新增编号，不读取解盲或源码。这属于同一 AI 的再次复评，有先前材料影响的局限，必须披露，不当作第二位独立评审。

第二轮结果（2026-10-12）：连贯 16/18 → 12/18，三牌均分 1.00 → 1.44，六对陪伴无明确增负，换末牌实质差异 5/6。连贯护栏仍未过，不能由平均分或偏好票数替代；候选保留，质量目标未完成。完整结果另存 `batch-0-v211-round2-review.json` 和解盲汇总，最终评分后不再修改候选，heldout4 标记已评审但未用于修订。若后续按这些问题改稿，先固定新留出，再将 heldout4 标记为已使用；不把同一批样本反复改到过关。

## 例外：v2.13 的人工环节由 DeepSeek 代审（2026-10-27，用户决定）

- 范围：只限 v2.13 批次 0 的两项人工环节，即方式审读表（526 组）和 6 例人工抽检。由用户自有 DeepSeek API 下的 Flash 模型，在全新上下文中完成。
- 记录：结论写入 `aiReviewed`（审读表）和 reviews.json 的 `aiReview`（抽检）。`reviewed` 和 `humanReview` 保持空，不得回填。抽检沿用第 5 步的评分规则：五项各 0–2 分，每例 ≥8/10 且没有单项为 0。
- 口径：放行报告与 PLAN 必须写明“未经人工审核，由 DeepSeek 代审”。第 9 行的判断不变：规则和测试守不住质量判断，AI 评审之间也可能有共同偏好，真人是否觉得有用仍是未验证项。用户事后补做人工审核，结论另记，不覆盖 AI 记录。
- 不外推：其余批次是否也由 AI 代审，须另行决定；本例外不自动沿用。

## 评审口径（2026-10-27，用户裁定，后续盲评沿用）

- 陪伴意图的换牌对：行动由末牌给出；只换阻碍位时，看读法一和阻碍说明是否随牌有实质变化，不因行动相同而判为无变化。
- 换末牌：读法一与追问来自阻碍位，本就不变。行动换成另一种观察方式或做法，即使回答的是同一个标准，也算实质变化；行动逐字相同或只换了措辞，判为无变化。
- 两条都写进匿名评审材料的评分说明（`evals/print-v213-final5.test.ts` 起），不在看到结果后另行调整。
