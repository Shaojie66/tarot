# 本地解读 v2 写作规范（扩写用）

> 来源：v2.1–v2.7 十轮 AI 盲评（`docs/review-local-reading-ai-prescreen-2026-10-10.md`）和 PRD（`docs/prd-local-reading-quality-2026-10-10.md`）总结出的规则。**规则里能自动检查的，都已写进测试**（`evals/local-quality.test.ts`、`evals/local-sweep.test.ts`）；这里写的是测试查不出来的判断。内容文件：`content/local-reading-v2.json`。

## 1. 声音

- **直接给出可核对的主张，再说怎么核对。**允许写“这组牌的重点是……”“先看清承诺，再决定放下哪一项”；不写“这三张牌不是答案”“我不替你做决定”这类免责。选择权靠结果页的“就做这个 / 改成我的版本 / 这次先不做”保障。
- **关于用户的处境、情绪、他人想法、关系，只用可以被否定的口径**：“可能……”“如果……”“……时”。关于**牌**的象征可以直说（“宝剑四讲的是暂停”）。
- 一句话里只放一层意思。评审多次指出“一行塞三层意思”（稳住自己 + 不必急着碰 + 期限例外）读起来是拼接。

## 2. 不要写（评审反复指出的）

| 类型 | 例子（不要写） | 改成 |
|---|---|---|
| 替用户确认状态 / 情绪 | “你其实已经知道……”“你只是还没……”“不安被压下”“情绪起伏是……” | “如果有一件事一直拖着，……”“可能在提示……” |
| 把状态当标签、再当行动 | “「X」是眼下的底色，「Y」是可以先动的一步” | 一句话要点（`oneLine`）+ 条件句，Y 不能是个要避免的状态 |
| 预设用户做过 / 有过 / 想过 | “你想了很久的计划”“你已经学到的”“想学的东西已经明确时”“刚才那件小事”“当初答应是出于‘应该’” | “如果有……”“如果已经……” |
| 预设用户要离开 / 要改变 | “走之前必须先处理……”“继续维持原样每个月要付出什么” | “如果要走一段过渡，……” |
| 替用户判断他人 | “对方不重视你”“双方没有在一起建造什么” | 只写成用户可以核对的问题 |
| 断言词 | 一定 / 注定 / 必然 / 肯定会 / 命中注定（`BANNED_PHRASES`）、`ASSERTIVE_PHRASES` | — |
| 通用安慰 | “你的价值不取决于别人有没有看见”“你的状态其实不差” | 说这次具体要核对什么 |
| 与问题无关的比喻 | “刹不住的自行车”“像在审一份合同” | 只用能直接对应牌面意象的 |
| 要求读者认领未确认的处境 | “原来的安排可能已经不像从前那样稳，先承认这一点”（前半句留了余地，后半句仍要求认领） | “如果原来的安排已经不像从前那样稳，可以先把这一点看清”（`先承认` 已进 PRESUPPOSED 扫描） |
| 整体点题与行动脱节 | 整体说“比较两边成本”，行动只排序在意的事 | 要么行动真的做这件事，要么把核对点收窄到行动能完成的范围；检查：核对点（`obstacle.focus`）与末牌三种意图的行动能否一句话接上 |
| 无具体问题时预设用户有目标 | “今天只学一个很小的东西”“做完记一句收获” | 写成可以不做的条件句：“如果今天有一件想碰一下的小事……没有也可以，不碰也算完成” |
| 合作类牌的行动只剩单人练习 | decide 试验只写“想得到什么信息” | 选项依赖别人时，把“需要谁、配合什么”写进试验要验证的信息 |
| 整体复述逐牌说明 | 整体与某张牌的说明逐字相同 | 整体用该牌的 `oneLine` |

## 3. 延后类建议必须带例外

凡是建议“先不处理 / 延后 / 暂放 / 挪到明天 / 其余明天再说 / 等稳下来再……”，同一句里必须有“不紧急”或“有期限的事以期限为准”（测试全文扫描）。**只有真的在延后什么时才加**——喝水、慢呼吸这类行动不延后任何事，不要加（评审认为是补丁）。

## 4. 行动

- 一个人 24 小时内能独立做完；有对象、步骤或完成标准（“写下……”“选一件……给它二十分钟”“……做完就够了”）。
- **涉及关系的主题，行动只涉及用户自己**（“只写你自己的部分”），不预设联系、约、发消息给对方，不预设“一起”。
- 三种意图是三种任务，不是三种语气：
  - `clarify`：帮人分清一个关键区别。
  - `decide`：给比较标准、信息优先级或可逆的小试验，**不替用户选**。
  - `companion`：降低负担，仍围绕牌面；不强制写字、列清单、核对；不预设有一件事要处理。
- 不要在行动后面追加“做的时候留意……”（已删除；硬接的尾巴被评为脱节）。

## 5. 读法与追问

- 两条读法必须是**不同的条件、不同的下一步**，且以“……时，”或“如果……”开头（测试检查）。不写“从外部看 / 从内在看”的固定二分。
- 追问是开放式：以“？”结尾，不以“吗 / 是不是 / 要不要”收尾，不预设用户没提过的人或事（“如果……”开头的条件问句可以）。

## 6. 每个朝向要写的字段

见 `content/local-reading-v2.json` 里已有的牌。每张牌 `upright` / `reversed` 各一份：

| 字段 | 用途 | 要求 |
|---|---|---|
| `gist` | 兜底路径里的标签（极短） | 2–8 字 |
| `oneLine` | 整体综合三张牌时用 | **以“可能……”开头**的谓语；与本牌的 `situation` / `obstacle.text` / `next.text` 不是同一句，也不含它们的原话 |
| `tags` | 选共同解释用 | 用已有词表（见 §7）；每个朝向 1–3 个，不要为凑命中加不贴切的标记 |
| `situation` | 在“此刻”位置的说明 | 描述牌在这里的提示，条件口径 |
| `obstacle.focus` | 在“阻碍”位置时，整体里的“值得先核对的是：……” | 一个**有没有 / 是否 / 对不对得上**式的核对点，不是对用户的判断 |
| `obstacle.text` / `.check` | 阻碍位说明 / 读法一 | `check` 以“……时，”或“如果……”开头 |
| `next.text` / `.check` | 下一步位置说明 / 读法二 | 同上 |
| `next.actions.{clarify,decide,companion}` | 三种意图的行动 | 见 §4，`{in}` 会被替换成“这份工作里 / 这段关系里 / 这件事里 / 这个选择里” |
| `next.question` | 追问 | 见 §5 |
| `byTopic.<topic>` | **只在**该牌在某主题下语境错配时才写（比如关系里读成职场协作、自我里读成“过渡”） | 可覆盖 `gist` / `oneLine` / `obstacle` / `next` 的部分字段 |

**警惕的牌族**（评审里反复在主题上出问题）：合作 / 分工类（星币三、权杖三）→ 关系主题要改成“期待”；学习 / 练习类（星币侍从、星币八）→ 去留主题不要变成“安排学习”；离开 / 过渡类（宝剑六、死神）→ 关系、自我主题不要预设“要走”。

## 7. 标记词表与共同解释

- **标记**（`tags`）用于选共同解释，不是给用户看的。已用：`solitude reflect avoid upheaval aftermath ending ending-resist transition transition-stuck warmth enthusiasm energy depletion self-doubt pace-fast momentum pace-snag pace-rushed small-liking sensitivity emotion-high rest restless restart decisive consequence juggle overload cooperate cooperate-gap trial start-small plan-no-action`。**新增标记要在这里登记**（一句话含义），并说明哪个共同解释会用它。
- **共同解释（focus）** 现有 5 个：`small-trial`（节奏与试验）、`warm-juggle`（热情与兼顾）、`load-transition`（负担与过渡）、`settle-feelings`（安顿与恢复）、`invest-cooperate`（投入与配合）。扩写到更多牌后**要新增主张**（例如大阿卡纳里的“自我认同”“转折与代价”“关系与边界”），新增一个主张需要：≥3 张牌的标记能命中它、`roles` 覆盖每个用到的标记、两条读法围绕同一个条件、三种意图的行动与追问、关系 / 自我 / 去留的变体检查，并**先写预先保留的组合与期望命中**（`evals/local-quality/reserved.json` 的做法）再看输出。
- 没有命中主张的组合走按位置的路径（整体 = 核对点 + 三张牌的 `oneLine`）。命中率是质量指标之一：`evals/local-sweep.test.ts` 会打印各主张的命中分布，当前 12 张牌里约 59% 的组合没有命中主张。
