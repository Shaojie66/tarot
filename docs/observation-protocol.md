# 首次使用观察协议（3–5 人）

目的：看真实的人能不能不被指导地用起来，并发现文案、流程的问题。**不是**效果评估，不能包装成"有疗效"或"普遍有效"的证据。

## 开始前
- 邀请 3–5 位不熟悉本项目的人；告知：这是反思工具，不预测未来；可以随时停下；他们写的内容由他们自己决定是否告诉观察者（用示例问题也行）。
- 用观察者自己的设备或一台干净的浏览器，**不要**事先演示。观察者不看用户输入的内容，除非用户主动给。
- 准备两个计时：
  - **系统等待**：点击到出现结果的时间（AI 路线才有意义；本地几乎为 0）。
  - **用户思考**：在起问、自解、读法选择、小行动上停留的时间。
  - 两者分开记，任何"总共几分钟"的结论都要注明构成。目前"一小会儿"只是体验目标，不是承诺。

## 任务（不给提示，只念任务）
1. 用这个应用问自己一个问题，抽牌，看解读。
2. 对小行动做一个你自己的决定（接受、改、不做都可以）。
3. 把这次记录找回来（刷新页面或换个入口）。
4. （可选）回看时写一句感受。

### 补充任务（N2 已实现，可以执行；目前**没有任何参与者结果**）

合成的到期回读与冲突备份已准备在 [observation/](observation/README.md)，避免要求参与者等 3–7 天或交出私密记录；每位参与者的记录用 [观察记录单](observation-session-sheet.md)。原有任务保持不经演示：

5. 回到一条到期记录，看看当时写了什么，然后结束这次提醒；可以不写笔记、不执行小行动。
6. 查看一次本次意图与 AI 发送说明，说明选择本地 / AI 各会发生什么；不要求实际付费调用。
7. 在合成数据环境查看导入冲突预览与失败提示，解释哪些内容已保存、哪些未保存；不操作参与者的真实资料。

只记录任务成败、需要的提示与用户原话。任何人误以为“已回看等于行动已完成”“偏好绝不发给模型”“失败提示等于所有内容都回滚”，都应登记界面或文案问题，不用平均完成率掩盖。上述任务发现的需要才作为微定向或回望页重新排期的依据。

## 记录
| 观察项 | 记什么 |
|---|---|
| 无需指导完成 | 每一步是否卡住、卡了多久、问了什么 |
| 理解"非预测" | 事后问："你觉得这个应用在告诉你什么会发生吗？" 原话记录 |
| 可以拒绝行动 | 是否注意到"这次先不做"；有没有觉得被要求去做 |
| 知道保存在哪 | 事后问："刚才的记录存在哪里？" |
| 回读可结束 | 是否找到完成 / 不再提醒；是否理解打开详情本身不会结束；与行动复盘是否混淆 |
| 理解发送范围 | 是否知道本次意图在 AI 解读 / 换视角时发送，主题偏好与回读节奏不需要发送 |
| 理解数据操作结果 | 能否从提示分辨新增、保留、冲突与分项失败；是否出现虚假的安全感 |
| 困惑 / 不适 | 任何一步的皱眉、停顿、"这是什么意思" |
| 文案 | 哪句话读不懂或太强硬 |

## 事后三个问题
1. 哪一刻最有帮助？哪一刻最多余？
2. 有没有哪句话让你不舒服？
3. 你会再用吗？什么情况下？

## 处理
- 每位观察对象一页记录，**不记真实姓名与问题原文**，只记编号。
- 汇总：共性问题 → 提 issue / 改文案；个别意见单独标注。观察结果写入 `docs/` 的评审记录，不进代码仓库的个人信息。
- 出现明显不适或危机信号：先停止观察，按求助资源页处理，不继续任务。
