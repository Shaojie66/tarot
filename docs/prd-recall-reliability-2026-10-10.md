# 下一轮 PRD · 可控回读与可信数据

> 日期：2026-10-10；基线：v1.2 / `c164557`；状态：评审建议，尚未实施。
> 排期与依赖：[PLAN v1.3](PLAN.md)；问题证据：[技术复评](review-v1-2-2026-10-10.md)。本 PRD 修订此前“未来回读”的未完成部分，不推翻已确认保留首访建档的决定。

## 1. 这轮解决什么

让用户完成三件小事：知道本次解读会用什么信息；过几天找回一条记录并结束提醒；导入备份后不担心已有内容被悄悄替换或删除。

情境卡、首访建档和日记本视觉已经足够支撑这些任务。当前没有参与者证据证明需要更多问答或统计页面；“回读会提高留存”“笔记填写率低”等只能是待验证假设。本轮成功不以新增功能数、测试数或连续使用天数衡量。

## 2. 范围与取舍

| 决策 | 下一轮要求 |
|---|---|
| 首访建档 | 保留，可跳过，不阻断点卡；说明这是长期默认偏好。避免强制第三屏，回读节奏可放在设置或结果页 |
| 本次意图 | 默认继承偏好，可在现有抽牌前界面选“仅本次调整”；未操作不多走一步；此刻卡默认陪伴 |
| 回读 | 完成单条安排 → 到期 → 进入回看 → 完成 / 不再提醒。只做站内提示 |
| 备份 | 保留回读与建档的可选字段和旧备份兼容；容量、冲突与失败反馈优先于新导出格式 |
| 暂缓 | 微定向 0–2 题、自解默认收起改造、额外反思提示、回望统计页、情绪趋势、更多牌阵和美术支线 |
| 不纳入 | 系统推送、行动督促、打卡、完成率、云同步、账号、埋点，以及独立的 followups 存储 |

“小行动是否做了”和“是否回看过”互不推断。用户读一遍就走、拒绝行动、不写笔记都应是正常路径。

## 3. 回读的最小完整旅程

### 保存以后：自动默认可见，单条记录可改

只有正式记录保存成功，才可为它安排回读。没有默认节奏时不自动创建；有默认节奏时给出真实结果，例如“记录已保存，已安排 3 天后回看”，旁边可选“调整 / 不提醒这条”。提示不能只根据内存状态出现。

本次可选“不用 / 3 天后 / 一周后”。新设置与重新安排均从用户确认时刻起计算 72 / 168 小时；展示明确的本地日期时间，避免把固定小时数误称为所有时区下同一钟点。此轮不增加任意日期选择器。

一条记录只有一个回读。重复保存、刷新、重复点击不新增；更改默认节奏只影响后续新记录，不改变已安排或已结束的提醒，也不对旧草稿恢复出的结果补发提醒。旧记录需要用户主动安排。

记录保存成功、回读写入失败是两个结果：“记录已保存，回读没能保存，可以重试。”不能用一条笼统的保存成功掩盖提醒失败。

### 到期以后：直达回看，选择含义明确

首页和历史页保留一条克制的提示：“有一条记录到了回看的日子。”提供“去回看”和“不再提醒”。多条到期时显示数量并按最早到期优先，处理一条后再显示下一条，不增加消息中心。

“去回看”打开对应详情并定位 / 聚焦“回看”区；只打开页面不改变状态。“不再提醒”永久结束该条提醒，写入成功后才移除提示。本轮不做延后功能，因此移除当前“先不管”这种临时性暗示。

详情回看区提供两个可独立完成的选择：

- “已回看”：不要求写字，成功后标为 done。
- “保存回看并完成”：用户可选情绪、笔记、行动复盘；先确认回看内容保存，再结束该条提醒。笔记已保存但提醒更新失败时明确分项反馈，只重试剩余步骤。

已有的普通“保存回看”能力可以保留；修改历史笔记不应暗中改变用户没有选择处理的提醒。不要根据页面停留时间或填写某个字段猜测用户已完成回读。

### 状态语义

| 当前状态 | 用户操作 | 成功后的状态 | 失败后的表现 |
|---|---|---|---|
| 无提醒 | 明确安排，或新记录采用已选默认 | pending | 不显示安排成功，可重试 |
| pending | 打开详情 | pending | 保持原提醒 |
| pending | 已回看 / 保存回看并完成 | done | 保存分项状态，不隐藏未完成提醒 |
| pending | 不再提醒 / 不提醒这条 | dismissed | 保持提醒，解释未能保存 |
| pending | 调整到 3 / 7 天后 | pending，更新到期时间 | 保留旧时间 |
| done / dismissed | 在详情主动重新安排 | pending，更新同一条回读 | 保留原状态，不自动复活 |

到期与状态变化在页面返回前台、跨标签页更新、页面跨到期时间时刷新；组件离开时取消订阅和定时器。不存在的记录不能形成永久提示，清理失败必须能被识别和重试。

## 4. 偏好与发送说明

首访问题改为“通常更希望从这里获得什么帮助？”，选项继续沿用理清 / 决定 / 陪伴。解释建议为：“偏好保存在这个浏览器中，之后可在设置修改。选择 AI 解读时，本次想要的帮助也会发给你配置的模型。”

抽牌前在现有页面显示当前意图，提供可选的仅本次调整，不新增必答页。本次意图在抽牌时固定，进入请求和记录快照；此后改变全局偏好不重算当前结果或旧记录。下一次恢复默认；此刻卡默认陪伴，若用户主动调整则尊重本次选择。

| 数据 | 用途与边界 |
|---|---|
| 本次问题、可选自解、固定牌面、本次意图 | 本地模式不发给模型；用户选 AI 解读 / 换视角时按操作发送，重试可能再次发送 |
| 主题偏好、回读默认节奏 | 仅用于本机入口排序与提醒，不需要向模型发送 |
| 笔记、情绪、回读状态 | 本机保存；不因为回看自动启动 AI；分享仍按原白名单 |
| 私密完整备份 | 用户主动下载的明文恢复文件，含记录、每日牌、回读与建档；不含草稿、key、设备信息；独立设置不随备份覆盖 |

“本地保存”不再写成“任何答案只存在这台设备”。全程本地、已发送后改用本地、AI 重试三种情况沿用现有准确说明，并补 intent。

## 5. 数据操作的产品契约

导入前预览新增、相同、冲突、回读 / 每日牌容量和是否采用建档；默认保留本机版本。确认时若数据已变化，应说明“本机内容有更新，请重新核对”，不能沿用旧选择覆盖新内容。本机已建档时一律不被备份建档覆盖。

容量不够时，本轮默认拒绝整个导入且不写入，告诉用户哪类数据超限；不自动清理任何旧记录或提醒。用户若要整理数据，走现有显式删除流程；本轮文档不执行删除。

所有字段先预检。运行时仍可能发生分项失败：页面应准确说明哪些已写入、哪些失败、哪些无法确认，提供重新读取和幂等重试；不能在未知时声称“没有写入任何内容”。退出或刷新后以重新读取的实际状态为准，不冒称可以恢复一个未持久化的导入进度。

导出时重新读取当前数据并显示数量、时点；读取失败或有无法解析的条目时，不得把可读子集叫“完整备份”。本轮优先中止完整导出并说明问题，不静默丢弃未知数据。

清空范围应明确列出记录、每日牌、草稿和回读；建档偏好与设置保留。任一项清理失败都不能提示“全部清空”。不新增重置偏好按钮作为本轮必需功能。

## 6. 可执行验收

| ID | 场景 | 通过标准 |
|---|---|---|
| AC01 | 跳过建档 / 无默认节奏 | 仍能本地抽牌并保存；不自动安排提醒，不多出必答步骤 |
| AC02 | 默认 3 天，完成一条新记录，反复刷新与保存 | 只有一条回读；明确显示实际安排时间；单条可取消 / 调整 |
| AC03 | 保存后把默认改为 7 天，再恢复旧结果 | 旧结果和原提醒不变；无提醒的旧结果不补发；只有新记录采用新默认 |
| AC04 | 到期 → 去回看 → 只读 → 已回看 | 定位回看区；打开本身不完成；明确完成后跨刷新不再提醒；小行动状态不变 |
| AC05 | 到期 → 写笔记 → 保存回看并完成；或不再提醒 | 分别得到 done / dismissed；原解读与选择不改；多条提醒顺序正确 |
| AC06 | 记录、笔记、回读分别写入失败 | 每种失败都可见，不报虚假成功；重试不重抽、不丢已存笔记、不重复记录或提醒 |
| AC07 | 页面跨到期时间 / 返回前台 / 另一标签页处理 | 提示同步实际状态；不存在记录不留死链接；监听被正确清理 |
| AC08 | 偏好理清，本次选陪伴，随后改全局偏好 | 本次请求与记录保留陪伴，下一次用新默认；发送说明涵盖 intent，本地路线 0 模型请求 |
| AC09 | 键盘与窄屏完成上述操作 | 不出现强制额外屏；所有操作有名称与可见焦点，定位回看区不抢其他普通导航焦点；取消 / 拒绝同样可达 |
| AC10 | 容量满、重复回读 ID、坏日期、未来版本备份 | 写入前拒绝，已有数据逐项不变；旧合法 v1 备份仍能导入 |
| AC11 | 预览后本机新增 / 修改 / 删除记录或完成建档 | 提交复核发现变化；默认不覆盖，不复活已删除记录，不产生孤立回读 |
| AC12 | 导入中断、补偿失败、重复重试；导出前其他标签页写入 | 不谎报全回滚；实际分项结果可核对；重试无重复与静默损失；导出包含最新已确认数据 |

AC01–AC09 是 N2 交付门槛，AC10–AC12 是 N1 交付门槛；涉及两者的失败路径必须联调。验收记录写实际结果，不预先勾选通过。

## 7. 用真实观察决定后续功能

沿用 [首次使用观察协议](observation-protocol.md)，3–5 人使用合成或自选问题，记录能否不经指导：完成抽牌；知道发送内容；结束回读；分辨已回看与行动已做；理解一次导入的结果。只记录编号、任务成败与卡点，不记录个人问题正文，不加入埋点。

目标是所有参与者都能理解这些关键操作；若一人因界面或文案误以为“已安排 / 已清空 / 完全不发送”，就记录问题并修整，不能以平均完成时间抵消。小样本只用来发现问题，不宣传留存、疗效或普遍易用性。

微定向、额外反思提示或回望页只有在观察呈现具体未满足任务后才重排。旧方案的竞品断言缺少仓库内可追溯证据，本轮不把它们当成已验证的需求依据。
