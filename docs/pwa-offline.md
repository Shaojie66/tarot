# PWA 与离线：行为、限制与验收矩阵

"离线"在本项目里有三个不同的能力，别混用：

| 能力 | 含义 | 何时具备 |
|---|---|---|
| 不调用模型（本地模式） | 解读由牌义 + 规则模板生成，不发任何内容给模型 API | 随时，无 key 也行（M2） |
| 断网重开 | 访问过的页面断网后仍能打开、能走完本地流程、能看历史 | 安全上下文 + service worker 已接管（本文） |
| 可安装 | 添加到主屏幕，独立窗口打开 | 安全上下文 + manifest（本文） |

## 缓存策略（`src/features/pwa/sw-source.ts`）

- **静态资源**（`/_next/static`、`/decks`、`/icons`）：cache-first。
- **页面与 RSC 请求**：network-first，成功就更新缓存；断网回退到上次缓存；没缓存过的导航返回一个“离线说明页”（503）。
- **永远不拦截、不缓存**：`/api/*`（含问题与结果的请求和响应）、`/sw.js`、非 GET、跨域。有测试断言缓存里没有任何 `/api/` 条目。
- 页面是静态外壳，不含用户内容；用户的记录在 IndexedDB、草稿 / 每日一张 / 设置在 localStorage，与 SW 缓存无关。
- 安装时预缓存：`/`、`/reading`、`/daily`、`/history`、`/settings`、`/cards` 及它们引用的脚本 / 样式。

## 更新

- 新构建的 `sw.js` 带新的构建号。新版本安装后**不自动接管**：页面底部出现“有新版本”横幅，点“立即更新”才切换并刷新（避免旧页面拿不到被清掉的旧资源）。不点，则在所有标签页关闭后下次访问自动用新版本。
- 新版本激活时只清理旧版本的 `tarot-*` 缓存，不动别人的缓存。

## 验收矩阵

| 场景 | 预期 | 验证 |
|---|---|---|
| 首次访问就断网 | 打不开（没有任何缓存可用）。必须先在线访问一次 | e2e：断网 `goto` 抛错 |
| 在线访问后断网，刷新 | 页面正常 | e2e（Chromium，真实 SW） |
| 断网，客户端跳转到预缓存页面 | 正常 | e2e |
| 断网走完一次本地占卜并保存 | 正常；`/api/status` 失败 → 视为无 AI，只有本地解读 | e2e |
| 断网打开 `/history` | 列表从 IndexedDB 读出 | e2e |
| 断网打开从没访问过的页面（如 `/history/<某 id>`） | 离线说明页 + 回首页链接 | e2e |
| 断网时 AI | 不可用，自动只剩本地解读，不报错 | e2e |
| API 响应是否被缓存 | 否 | e2e + 单测 |
| 新版本发布 | 横幅提示，确认后才切换；旧缓存被清除 | 单测（SW 源码在 vm 里跑）+ e2e（用桩验证横幅逻辑）；**真实浏览器里的 SW 更新流程没有端到端验证** |
| 局域网 `http://IP` | 不注册 SW，无离线 / 安装；页面在线可用 | 浏览器规则；`isSecureContext` 为 false 时不注册 |
| iOS Safari / Android Chrome 真机 | 待验证 | 见 [device-checklist.md](device-checklist.md) |

## 已知限制

1. **离线首次打开 `/history/<id>`**：详情页的 id 来自服务端渲染的参数，没访问过的 id 没有缓存。从列表点进去在线时会被缓存，之后离线可打开。
2. 首次访问必须在线；缓存的是你访问过的页面，不是整站。
3. 局域网 http 访问没有离线能力（见上）。
4. iOS 对 PWA 有自己的限制（存储可能被系统清理、独立窗口里的 IndexedDB 与 Safari 标签页是分开的）：从主屏打开的“应用”和在 Safari 里打开的是两份数据，换入口前先导出备份。**这一条是公开资料中的常见行为，本项目未在真机上验证。**
