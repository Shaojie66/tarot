# 本地解读质量 · 技术复评与改造建议

> 日期：2026-10-10；基线：`2ed0aba85f270b35ef71012a55407dd0ee1795f1`，核对时与远端 main 一致。
> 范围：当前本地生成器、内容模板、结果页、测试与计划。只修订文档；未改代码、内容 JSON、prompt、测试或配置，未请求模型 API。
> 对应 [产品 PRD](prd-local-reading-quality-2026-10-10.md) 与 [PLAN v1.4](PLAN.md) 的 L1–L3。用户明确不满意的是本地解读，v7 AI prompt 不是本轮首因。

## 1. 技术结论

`buildLocalReading` 是确定性的拼接函数。它接收问题正文，却不读取正文；整体是牌名与关键词清单，两种读法只拼第二、第三张牌的现成字段，行动和反问的分支很少。因而当前问题同时来自内容和生成结构，不能靠改几句柔和措辞解决。

可继续使用当前前端与存储架构。最低成本路径是先建立正向的编辑标准，随后加入有限的本地内容映射与组合规则。没有依据要求换框架、引入网络模型、枚举全部三牌组合或增加数据库表。

## 3. 本轮验证

使用 Node 在内存中转译并加载当前 TypeScript，只执行本地纯函数；未写入真实历史记录、浏览器存储或测试文件。

| 探针 | 实际结果 |
|---|---|
| 同为 relationship / clarify，同三牌，问题从“每次约定临时取消，怎么谈”改为“沟通很好，计划周末活动” | 序列化后的整个结果完全相同 |
| 同一输入增加“这三张牌让我想到合作挺顺利”的自解 | 只有 overall 前置引用变化，其余字段完全相同 |
| 固定事业主题和后两张，仅替换首张 | 两读法、行动、反问完全不变（独立技术审查的内存探针） |
| 固定事业主题和前两张，遍历其他 76 张正位作为末牌 | clarify 共 5 种行动；decide / companion 各仅 1 种行动、1 个问句（独立技术审查的内存探针） |

这些结果说明分支结构的实际限制，不代表 76 张牌语义都该不同，也不应改成“换任何一张牌必须换一个同义句”的测试。应选择牌义方向确实相反或位置职责不同的对照，检验是否发生了有理由的变化。

本轮 `pnpm check` 通过：lint、类型检查、30 个测试文件 / 508 项测试。文档链接、源码行号范围、Markdown 代码块与 `git diff --check` 检查通过；改动范围仅为 8 份 Markdown。Node 有非阻断性的 `--localstorage-file` 提示。没有更改页面，本轮未重跑全部 E2E；已有 v6 / v7 模型报告只作历史证据，不是此次新实测。这些通过不代表 L1–L3 已实现或内容质量已经达标。

## 4. 分阶段设计

### L1：先改变内容标准和最显眼的表达

职责：产品编辑确定 PRD 中的 16 个样稿，前端随后修改 `content/local-reading.json`、结果页说明和相应测试。当前回合只制定规格。

- 首段取消固定免责声明开场，先给内容；关键词列表不再承担整体解释。
- 能力说明集中在来源 / 模式处，拒绝权由现有按钮保障；危机、错误、隐私发送说明不属于应删除的重复文案。
- 默认关系行动应能由用户独立完成，但不必出现“只写给自己”五个字；“写一份合作提议”可以是独立完成的动作，不能因为包含“一起”就自动被视为已强迫接触对方。
- decide 的标准是比较与验证，不是固定后退；companion 的标准是低负担且贴牌，不是永久关闭行动。
- 测试不再要求精确的防御性短语。保留必要的危机 / 牌面 / 数据契约断言，用场景测试与编辑审读替代过宽的联系词正则。

这一步只能先修语气和呈现。必须在发布说明中诚实保留“自由文本未理解、组合规则待完善”的边界，不能借 L1 宣称已经实现完整的 L2。

### L2：有限且可审阅的本地内容组织

继续保持 `ReadingRequest`、`ReadingResult` 和记录结构。建议新增一个独立的本地内容映射文件，例如 `content/local-reading-v2.json`（候选路径，当前未创建），避免直接把百科整段当作个性化解读；不新增目录。

内容设计先随样稿确定，不先造庞大的标签系统。每个正逆位至少有可审查的观察方向，以及在此刻 / 阻碍 / 下一步位置上的短片段；需要主题变体时再补。动作方向可以从核实、试验、协调、设边界、调整投入、恢复余量等小集合开始，不要求每张牌只归一类。

建议组织顺序：

1. 按三张牌、正逆位、位置找到经过编辑的片段和有限方向标签，保留各自来源。
2. 选择一个主线关系，例如“推进与暂停”“投入与协作”“过渡与资源”；只使用可说明理由的规则。没有命中组合规则时，使用三个位置逐步展开的回退，不编造心理结论。
3. 用三个位置的贡献组成整体判断；第二、三张不能掩盖第一张。逐牌说明应能支撑这个判断。
4. 从主线生成两条不同的核对路径，写清各自适用条件；不能仅把 topic 换成 self 作为第二种读法。
5. 按末牌具体行动方向、主题、意图选择行动和追问；intent 调整任务负担与目的，不覆盖成全局固定一句。
6. 用现有 schema / 牌面一致性 / 内容红线检查输出；缺失映射走可读回退，不崩溃、不联网补齐。

目标是编辑能解释“为什么选了这一段”。不要为了让快照测试变绿随机抽同义句，也不要以标签数量、独特字符串数量或组合覆盖率代替内容质量。不枚举 78 张牌的全部三牌组合。

**不处理的能力：**本轮不从任意问题正文自动推断事实、情绪、关系状态或意图；不加关键词匹配伪装理解。原文与自解可以在既有输入 / 回看位置展示，本地生成器只对其确实使用的输入作能力声明。之后若要问题级理解，另立方案，不挤入本地文案修复。

### L3：内容质量与工程验证分开

自动测试负责稳定性和边界：相同输入稳定输出、牌面不变、全 78 张正逆位有映射或明确回退、三个位置受支持、输入合法时不崩溃、全程 0 模型请求、记录按原快照保存。保留原本危机和存储回归。

人工 / 产品审读负责质量：有无观点、三牌关系是否成立、主题是否匹配、行动是否有效、语言是否直接。按 PRD 冻结的 16 例和 8 个定向对照逐项记录；AI 可预审，不能代替用户或编辑的认可。

有意义的反例包括：

- 将阻碍位的“需要停止”换为“需要配合”，不能仍得到同一类建议而无解释。
- 将下一步从核实信息换为恢复余量，decide / companion 不应仍被同一句行动覆盖。
- 交换当前与阻碍的位置，解释应随位置职责变化；牌 ID 与朝向仍精确匹配。
- 用户没有提供他人的事实，本地结果不能宣称“对方不重视你”或“双方没有合作”。
- 缺少自由文本理解时，不能把问题复述作为“语义匹配通过”的断言。

涉及页面改动时按项目规则执行 `pnpm build`、`pnpm e2e`；内容 / 规则改动执行 `pnpm check`。不为纯文档再增加镜像实现的测试。

## 5. 版本、历史与实施边界

- 旧记录已经保存完整结果快照，继续按原结果读取，不自动用新模板重写历史。
- 本地内容改动必须有版本标识，可使用现有 `versions.content` 字符串表达牌义版本与本地组织版本；具体命名在实现前固定。不要为此扩展记录 schema 或做数据库迁移。
- 修改共用牌义文件可能同时影响本地、百科和 AI 注入；优先在独立本地映射里实现新的表达，同时登记需要单独修正的原始牌义断言，验证相关消费者。
- L1 / L2 调整本地算法、JSON 内容、测试和 UI 是未来实施范围；本轮尚未执行这些变更。

## 6. 与 AI v7、旧评审的关系

v7 的“每句可否定”“理性拆解不下结论”确实也可能把表达推向退缩，但修改 `content/prompts/v7/` 不会改变当前本地路径。AI 输出优化应单独按同输入、同牌、同模型比较，不作为 L1–L3 的前置条件；本轮不生成 v8。

此前 v6 / v7 报告把断言句式减少视作改善，这只覆盖一个维度。“观点清楚且有依据”需要独立审读，不能由模糊词或禁词数量证明。既有 v7 主集 39/40 与此刻 3/4 应分开报告，所谓“2 例失败”是两个集合合计，不是主集 2/40。

N1 / N2 已有后续提交，不应把上轮全部数据问题和回读缺口复制成当前未修结论。本轮的主线是本地内容质量，原数据与安全约束继续作为回归底线。
