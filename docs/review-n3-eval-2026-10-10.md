## 1. 脚本改了什么

| 问题（复评 T07） | 现在 |
|---|---|
| “成功率”含修复重试，却被叫首轮 | 逐例记录 provider 请求数（`instrument` 包装 `provider.stream`）：首试成功 / 触发重试 / 靠重试成功 / 请求数未知分别计数；最终成功率目标 ≥90% 保持，首试率另报，不借用 |

## 2. 对既有 v5 / DeepSeek 报告的预审

报告：`tmp/evals/reading-live-2026-10-09T23-11-03-121Z.json`（提交 `036521d`，39/40 到 result）。读了 12 例（四主题各前 3 例）的全文，并对 39 条结果做了模式统计。按 README 的五条标准：

**统计（39 条结果）**

| 现象 | 数量 | 判断 |
|---|---|---|
| 反问以“如果不……”开头 | 38/39 | 句式几乎单一；多数仍是开放问，但“如果不用考虑他人评价”反复出现，可能把所有处境都暗示成“在意别人评价” |
| 读法一以“从外部看”开头（读法二“从内在看”） | 24/39 | 两种读法确实角度不同，但模板化；“外部 / 内在”二分不一定贴合问题 |
| 行动是“左边写…右边写…” | 17/39；含“三” 27/39 | 可执行、可拒绝，但形式重复 |
| 行动出现联系他人 | 3/39 | 其中 1 条是“主动发一条消息约对方 vs 再等一段时间不主动联系”，涉及关系时给出了联系选项，边界上违反“不预设联系对方”；1 条要求“今天发一条消息问出去”（求助对象未指定，但是祈使句） |
| 反问是封闭式（是 / 否可答） | 1/39 | “……你愿意先弄清楚它们是什么，再决定走不走吗？” |

**逐例观察（12 例）**：

- 最需要关注的是标准 2（凭牌面替用户判断处境、他人动机、关系结论）。例：`career-03` “一段已经走到尽头、你却还没正式告别的东西”、死神牌“其实你心里已经知道它到站了”；`crossroads-03` “你此刻并不缺爱和归属”；`relationship-03` “你付出的部分没有被回应”；`relationship-01` “你承担了太多维持的工作”；`self-03` “你隐约知道自己在用想象代替行动”。这些是把牌面联想写成了关于用户生活或他人行为的断言，`BANNED_PHRASES` 里没有“一定 / 注定”所以不会被拦，但语气已超出“反思工具”的定位。
- 也有写得好的：`crossroads-01`、`relationship-02` 基本都用“可能 / 也许 / 一种读法”，把结论留给用户，行动和反问也具体开放。
- `career-02` 的整体解读用“刹不住的自行车……容易撞到人”这类与问题关系不大的比喻，牌面到处境的推导偏弱。

**结论**：39/40 的结构与红线通过，不能推出语义合格。主要风险不是禁词，而是**断言式推断**与**句式固化**。

## 3. 建议（需要你决定，本轮没有改 prompt）

1. 新建 `content/prompts/v6/`（按 CLAUDE.md 不原地改 v5）：在 system prompt 里加“不把牌面联想写成关于用户生活、他人想法或关系的事实；只能以‘可能 / 也许 / 一种读法’提出，并给出可被用户否定的口径”；行动涉及关系时只给不需要对方参与的选项；反问句式不固定为“如果不……”，且不能以“吗”结尾可答是 / 否。
2. 评测里加一条**确定性启发式**（非语义判断）：对反问首词、行动是否含“联系 / 发消息 / 约”和是否以“吗”结尾做计数，作为报告项，不作阻塞；语义断言仍靠人工。
3. 人工审读：把这 12 例按 README 五条逐例打分后，再决定 v6 的改法。一人读不能替代多人，也不能证明改后更好。
4. 用 Anthropic key 或其他兼容模型重跑时，先跑新脚本得到首试 / 重试 / 意图 / 连续换视角的数据，再对比 effort 与是否升级 deep。
