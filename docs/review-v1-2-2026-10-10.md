# v1.2 产品与技术复评

> 日期：2026-10-10；基线：`c16455704a2e854d9c302f7224ad9e57a9f8936e`。
> 本轮核对时本地 HEAD 与远端 main 一致。范围：读取实现、执行现有检查、合成数据探针、修订文档；没有修改业务代码、测试、配置或 prompt，也没有调用真实模型。
> 执行入口：[PLAN v1.3](PLAN.md)；产品规格：[可控回读与可信数据 PRD](prd-recall-reliability-2026-10-10.md)。源码行号均相对于上述提交。

## 1. 判断

当前版本已经具备完整的单次使用路径。情境卡降低了起问负担，建档偏好已真正进入解读和入口排序，备份也覆盖了新增的回读与偏好。下一轮应停止扩大功能面，先把“保存以后发生什么”做可靠。

产品上，最明显的断点是回读没有完成出口：用户能进入旧记录，却无法通过产品操作将提醒标为已回看；“先不管”反而永久忽略。技术上，更紧迫的是导入可能挤掉已有内容、使用过期预览覆盖新数据，以及跨存储失败后给出不成立的“整批回滚”承诺。测试全绿与这些缺口同时存在，说明需要补行为覆盖，而非继续追求用例总数。

不建议现在做回望统计页、行动完成率、更多问答步骤或第二套提醒系统。首访建档保留，现有夜间日记本视觉方向保留；本轮没有完成新的视觉或真机验收，不能据此认定所有页面体验已经通过。

### 额外探针结果

| 探针 | 合成步骤 | 当前实际结果 | 下一轮期望 |
|---|---|---|---|
| R1 容量 | 先放入 200 条回读，再合并 1 条新回读 | 返回新增 1；总数仍 200；一条原有回读消失 | 拒绝超容量批次，原有 200 条逐项不变 |
| R2 重复 ID | 两条回读使用不同 recordId、相同 id，指向已知记录；预检后导入并忽略该 id | 预检接受；两条都变成 dismissed | 整个文件在写入前拒绝 |

| R4 建档变化 | 预览时本机未建档；之后本机保存 decide；确认导入 clarify | 本机意图被覆盖为 clarify | 重新核对，只保留已完成的本机建档 |
| R5 记录变化 | 预览将记录判为新增；之后本机保存同 ID 且含新笔记；确认导入 | 新笔记被覆盖丢失 | 在事务内发现变化，返回新冲突，不自动覆盖 |
| R6 恢复失败 | localStorage 写入回读成功；非法记录使记录批次失败；注入 localStorage 恢复写入失败 | 导入抛错，但刚写入的回读仍在 | UI 报告已写入 / 未写入 / 未能确认的分项状态，可重试；不得声称全部回滚 |

这些是函数级反例，不是对真实浏览器双标签页与崩溃的完整测试。实现修复时应将 R1–R6 固化为回归，并补真实浏览器里的并发与错误提示验证。

## 3. 按影响排序的问题

P1 表示下一版应优先关闭的数据、隐私或核心任务缺口；P2 表示需要明确排期或限制对外能力声明的缺口。本次没有将旧问题重新记为未修复，也没有发现需要重写架构的依据。

### T01 · P1 · 容量上限会静默删除已有内容

证据：[recall.ts:55](../src/features/recall/recall.ts#L55)、[recall.ts:77](../src/features/recall/recall.ts#L77)、[daily.ts:77](../src/features/daily/daily.ts#L77)、[daily.ts:127](../src/features/daily/daily.ts#L127)。回读新增和合并均截断到 200 条；每日牌合并后按日期排序截断到 400 条。后者可能丢本机旧条目，也可能丢导入条目，取决于日期。

R1 已实测回读丢失；每日牌由相同裁剪控制流静态确认。合并函数的 added 是候选数量，历史页成功提示又直接采用预览数量（[HistoryList.tsx:78](../src/features/history/components/HistoryList.tsx#L78)），不能代表最终落盘数量。

建议 N1：提交前计算容量，本轮默认整批拒绝超限导入；新增提醒失败时保留正式记录并提示未安排成功。返回实际新增、跳过、冲突与失败数量，禁止为了容纳新内容自动淘汰旧内容。验收覆盖 199+1、200+1、400+1、备份本身超过容量、重复导入、跨存储任一类别超限。

### T02 · P1 · 导入确认使用过期预览，可能覆盖后来的修改

证据：[HistoryList.tsx:60](../src/features/history/components/HistoryList.tsx#L60)、[backup.ts:209](../src/features/reading/backup.ts#L209)、[backup.ts:217](../src/features/reading/backup.ts#L217)、[storage.ts:127](../src/features/reading/storage.ts#L127)、[storage.ts:159](../src/features/reading/storage.ts#L159)。预览来自页面加载时的 records 和选择文件时的其他状态；确认直接 bulkPut，没有在事务内比较当前版本。profileApply 也没有在写入时重查 onboarded。

R4 / R5 已复现。相同风险还包括用户已选择覆盖后记录再次被修改，以及预览期间记录被删除后旧回读变成孤立引用。

建议 N1：预览只是说明，不能充当写入授权的永恒快照。提交时重新读取并比较；记录的比较与写入放入同一 IndexedDB 事务。发现变动则返回新预览，旧勾选不得默认授权覆盖新版本。localStorage 的并发协调须覆盖建档 / 回读等相关写入口，仅在导入函数里加锁不能解决其他写入竞争。验收用两个标签页建立明确的先后屏障，不靠随机压测碰运气。

### T03 · P1 · “整批回滚”及部分存储成功反馈不成立

证据：[storage.ts:123](../src/features/reading/storage.ts#L123) 的补偿快照只在内存里；restore 吞掉恢复异常；页面仍显示“没有写入任何内容（整批已回滚）”（[HistoryList.tsx:81](../src/features/history/components/HistoryList.tsx#L81)）。R6 已复现。进程中断、回滚期间另一标签页写入也不受这套补偿保护。

同类问题：自动安排回读忽略 addRecall 的失败返回（[ReadingFlow.tsx:133](../src/features/reading/components/ReadingFlow.tsx#L133)）；忽略提醒不反馈失败（[RecallBanner.tsx:39](../src/features/recall/RecallBanner.tsx#L39)）；删除 / 清空吞掉部分 localStorage 失败（[storage.ts:101](../src/features/reading/storage.ts#L101)）。本地读取失败时“记录没有丢，换回普通窗口就能看到”也超出了证据（[HistoryList.tsx:100](../src/features/history/components/HistoryList.tsx#L100)）。

建议 N1：保留现有存储布局，改为完整预检、分项持久化结果、刷新后重读及幂等重试；明确这是有限的失败恢复，不是跨存储事务。记录已保存但提醒未保存要分别告知；读取失败保留未知状态，不能当成空库后继续覆盖。若需要崩溃后也能证明全有或全无，另写 ADR 评估统一存储 / 持久化日志；涉及数据库 schema 或迁移须另行确认，不能夹带在本轮修复里。

### T04 · P1 · 回读备份的身份与日期校验不足

证据：[recall.ts:23](../src/features/recall/recall.ts#L23)、[backup.ts:178](../src/features/reading/backup.ts#L178)。预检只排除重复 recordId，没有排除重复 recall.id；时间字段只是 string，状态与 completedAt 没有关联校验。R2 / R3 已复现，一次操作可能更改两条提醒。

建议 N1：文件内 id 与 recordId 分别唯一；与本机同 id / 不同 recordId 作为显式冲突处理，不计为成功新增；日期必须可解析、统一规范化为 UTC，保证字符串排序含义一致；pending 的 completedAt 应为空，done / dismissed 应有有效完成时间。当前代码生成的合法 v1 备份应继续通过；旧异常条目保留并报问题，不静默修正或丢弃。跨容量、引用、日期校验全部完成后才写入。

### T05 · P1 · 回读只能进入，不能完成；“先不管”实际永久忽略

证据：[RecallBanner.tsx:36](../src/features/recall/RecallBanner.tsx#L36) 只跳详情，没有回看区定位；[HistoryDetail.tsx:197](../src/features/history/components/HistoryDetail.tsx#L197) 只更新 review；[recall.ts:63](../src/features/recall/recall.ts#L63) 的 markDone 未接入业务 UI。“先不管”调用 dismissRecall，语义是永久结束。

另有两个生命周期边缘：订阅只有本模块写入通知，页面跨过 dueAt、重新前台或其他标签页修改时不会自动重算；自动安排依赖当前 profile.recallCadence，恢复此前未安排提醒的旧结果可能因新偏好被安排（[ReadingFlow.tsx:114](../src/features/reading/components/ReadingFlow.tsx#L114)）。后者为静态控制流结论，未完成浏览器复现。

建议 N2：按 PRD 提供“去回看”“已回看”“不再提醒”，可写笔记也可只读；只在保存成功后结束相应提醒。默认节奏只影响新记录，旧记录必须单独操作；补前台 / 跨标签页 / 到期刷新，失败不假装完成。沿用已有 recall，不新建 followups，不把回读结束等同小行动完成。

### T06 · P1 · 建档隐私文案和意图作用范围不准确

证据：[ProfileOnboarding.tsx:27](../src/features/profile/ProfileOnboarding.tsx#L27) 写“答案只存在这台设备上”，同页又问“这次”；实际 profile.intent 在每次抽牌时取用（[ReadingFlow.tsx:219](../src/features/reading/components/ReadingFlow.tsx#L219)），解读提示词包含它（[prompts.ts:73](../src/features/reading/prompts.ts#L73)）。发送说明只列问题、自解、牌面（[ReadingFlow.tsx:663](../src/features/reading/components/ReadingFlow.tsx#L663)）。

没有发现本地模式偷偷调用模型的问题；问题是 AI 模式下说明不完整，以及一次回答被长期沿用。建议 N2 把首访改为“通常更希望获得什么帮助”，发送前说明含本次意图；用现有页面中的可选控件支持本次覆盖，不加必答流程。偏好在本机保存，不等于其派生值不会进入用户主动选择的 AI 请求。

### T07 · P2（AI 验收门槛）· 成功率和安全断言没有匹配文档要求

证据：[reading.live.ts:120](../evals/live/reading.live.ts#L120)、[reading.live.ts:154](../evals/live/reading.live.ts#L154)：统计 runAiReading 最终终态，包含自动修复重试；并非 README 原称的“首轮”。[reading.live.ts:203](../evals/live/reading.live.ts#L203) 分开列 missed / inconclusive / falseAlarms，但只对 missed 做零值断言。历史 v5 报告确有 2 例对照误拦，不能写成安全集全面通过。

此外，解读 rows 没保存轮换后的 intent / 请求快照；换视角 12 例没有 intent 且 already 为空，不能证明 v5 意图在连续换视角中的语义效果。元数据使用 fast 模型标识，深度模型另配时不能准确说明换视角实际使用哪个模型。

建议 N3：报告 firstAttemptSuccess、retryUsed、finalSuccess、每入口实际模型、每例意图与终态；区分 provider 请求数与 SDK 内部重试。分别断言明确危机不产出普通结果、要求分流的用例实际分流、明确非危机对照无误拦；技术失败单列未验收。新增有 / 无意图、此刻默认陪伴及已有视角上下文的样本。人工语义审读单独记录，不由 schema 测试代替。未知首试率写未知，不能反推。

### T08 · P2 · 备份导出可能遗漏另一标签页刚保存的记录

证据：[HistoryList.tsx:28](../src/features/history/components/HistoryList.tsx#L28) 加载后保存页面快照；[HistoryList.tsx:44](../src/features/history/components/HistoryList.tsx#L44) 导出该快照，同时现读 daily / recalls / profile。备份可能混用不同时刻的数据。读取文件也在大小检查前调用 file.text，20MB 限制未阻止大文件先进入内存。

建议并入 N1：导出前重读，说明快照时点；已有未知 / 不可读条目时不能把可读子集称为“全部完整备份”；检测导出期间的变动并重试或提示。文件选择后先查 File.size，再读文本。验收覆盖导出页面打开后另一标签页新增 / 修改 / 删除、数据读取失败和超大文件。

## 4. 本轮不应重复开发的内容

| 之前的关注点 | 当前判断 |
|---|---|
| 有 key 时仍能全程本地 | 已实现，有自动回归；保持 0 模型请求约束 |
| crisis 字段门控、请求取消与迟到事件隔离 | 已有实现和回归；本轮不重新登记旧缺失问题。增量预览与完成结果仍需分开描述 |
| 用户行动默认未决定、保存草稿恢复 | 已有实现，继续作为基线 |
| 结果页刷新重复创建同一记录的回读 | recordId 去重已修；本轮关注完成出口、容量与偏好变化 |

| 是否要接入其他模型 provider | 兼容 adapter 已实现；待做的是每个实际模型的验收，不是再做同类 adapter |

## 5. 技术取舍与交付门槛

保持当前模块结构。复杂度的根源是多个存储介质之间的承诺、UI 状态和失败结果不一致，不是缺少新的框架、后台服务或代理系统。N1 优先建立明确的操作结果，再由 N2 接通界面，避免先改按钮再补数据语义。

本地下一版的必要证据：R1–R6 反例不再成立；真实浏览器中的并发、失败反馈、回读完成路径通过；现有 check / E2E 无回退。AI 验收使用修正后的 N3 口径，真实设备与参与者观察归 N4。没有数据时保留待验，不能把下一轮目标写成已完成。
